# 👑 [기획서_387] 황실 콕핏(shinseon_cockpit.pyw) 비트겟 격리 마진(isolated) 동적 호환 & 50% 분할 청산 / 원클릭 주문 22002 오류 원천 완치 기획서

## 1. 개요 및 배경

- **발생 시각:** 2026-08-30 17:42:53 KST
- **발생 오류:** `[17:42:53] ❌ [50% 분할 청산 에러] bitget {"code":"22002","msg":"No position to close"}`
- **원인 분석 (진범 포착):**
  - 국왕 폐하의 비트겟 선물 계정은 **`격리 마진 (Isolated Margin, marginMode: "isolated")`** 모드로 운용되고 있사옵니다.
  - 그러나 `shinseon_cockpit.pyw` 내 비트겟 직접 발주 패킷(`QUICK_MARKET`, `CLOSE_50`, `EMERGENCY`)의 `marginMode` 파라미터가 과거 구형 기본값인 **`"crossed"` (교차 마진)로 하드코딩**되어 있었습니다.
  - 비트겟 거래소 매칭 엔진은 `marginMode: "crossed"` 주문이 들어오면 교차 포지션만을 탐색하므로, 격리 포지션을 쥐고 계심에도 불구하고 `"No position to close (청산할 포지션 없음, 코드 22002)"` 오류를 뱉어내며 50% 분할 청산을 거부한 것입니다!

## 2. 개발 및 수정 상세 명세

### 1) [수정] `shinseon_cockpit.pyw` - `BitgetMainDirectWorker` 주문 패킷 전면 동적 격리 호환
- **`CLOSE_50` (50% 분할 청산):**
  - 활성 포지션 정보에서 `margin_mode = str(pos.get('marginMode', 'isolated')).lower()`를 추출하여 패킷에 정확히 주입:
    ```python
    res = self.exchange.private_mix_post_v2_mix_order_place_order({
        "symbol": "BTCUSDT",
        "productType": "USDT-FUTURES",
        "marginMode": margin_mode,  # 'isolated' 또는 'crossed' 동적 100% 매칭!
        "marginCoin": "USDT",
        "size": str(half_qty),
        "side": close_side,
        "orderType": "market",
        "tradeSide": "close",
        "holdSide": hold_side
    })
    ```
- **`EMERGENCY` (비상 탈출 100% 시장가 청산 백업):**
  - 동일하게 `pos.get('marginMode', 'isolated')`를 주입하여 어떠한 상황에서도 22002 에러 없이 100% 즉시 청산 보장.
- **`QUICK_MARKET` (원클릭 시장가 진입):**
  - 기본 `marginMode`를 `"isolated"`로 설정하고, 기존 포지션이 있을 경우 해당 포지션의 `marginMode`와 100% 일치시켜 발주.
