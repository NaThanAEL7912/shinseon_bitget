# ShinSeon Bitget 기획서_174 (ZeroDivisionError 백그라운드 사망 진범 파악 및 스마트 스탑 완치안)

## 📌 1. 원인 파악 및 팩트 분석 (-1.9% ➡️ -1.8% 반등 청산 미발동의 스모킹 건)

폐하께서 보내주신 -1.73% ROE 화면과 AWS 서버의 실시간 익셉션 로그(`shinseon_server.log`)를 1:1로 정밀 추적한 결과, **-1.9%에서 -1.8% 반등 청산이 발동하지 않았던 100% 명백한 스모킹 건 팩트**를 밝혀내었습니다!

### 🔍 팩트 원인 분석:
```log
[2026-08-11 18:34:46] [ERROR] Task exception was never retrieved
coro=<ShinseonV35Engine.manage_v35_exit_guardrail()>
ZeroDivisionError: division by zero
```

1. **`entry_price_1` 0 나누기 예외(`ZeroDivisionError`)로 인한 감시 루프 전사 (결정적 진범):**
   - 수동 진입 또는 포지션 동기화 시 `self.entry_price_1`(1차 진입가) 값이 `0.0`으로 초기화된 상태였습니다.
   - L2673 위치에서 `pnl_from_entry_1 = (current_price - self.entry_price_1) / self.entry_price_1` 수식 연산 시 **`ZeroDivisionError: division by zero`가 발생하여 감시 엔진 루프 비동기 테스크가 즉시 사망(Task finished with exception)** 하였습니다!
2. **시각적 착시 현상:**
   - 감시 루프(`manage_v35_exit_guardrail`)는 이미 18:34:46에 예외로 사망하여 꺼져 있었으나, 텔레메트리 루프(`run_telemetry_loop`)는 계속 살아있어 화면상에 `(🛡 스마트 스탑 가드: -1.80% ROE 손절 감시 중)` 라벨을 계속 출력하고 있었습니다.
3. **반등 조건식 검증:**
   - -1.90% ROE 상태에서 -1.80% 오프셋 설정 시, `-1.80 > -1.90`이므로 **상승/반등 익절/손실보존 모드**(`live_roe_rounded >= -1.80`)로 정상 지정됩니다.
   - 그러나 0 나누기 예외로 감시 루프가 이미 전사해 있었기에, -1.80% 및 -1.73% 반등 시점에 청산 발주 코드가 단 한 번도 실행될 수 없었던 것입니다!

## 🛠️ 2. 정공법 완치 수술 상세 내역 (완료)

- [x] **[작업 1] 0 나누기 원천 방지 안전 가드 도입 (`shinseon_server.py` 완료):**
  - `entry_price_1` 및 `entry_price`가 `0.0`이거나 무효일 경우 0 나누기를 원천 차단하고 안전하게 0.0%를 반환하도록 수식 정화를 완료하였습니다:
    ```python
    ent1 = float(getattr(self, "entry_price_1", 0.0) or getattr(self, "entry_price", 0.0) or current_bitget_price)
    ent = float(getattr(self, "entry_price", 0.0) or current_bitget_price)
    pnl_from_entry_1 = (current_bitget_price - ent1) / ent1 if ent1 > 0.0 else 0.0
    pnl_pct = (current_bitget_price - ent) / ent if ent > 0.0 else 0.0
    ```
