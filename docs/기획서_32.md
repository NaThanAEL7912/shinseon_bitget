# [기획서 32] 부팅 레이스 컨디션 수술 및 웹소켓 연결 직후 100% 자동 동기화 원천 복구 (V4.37)

## 1. 개요 및 스크린샷 팩트 분석
- **폐하의 지적 사항:**
  "자 로그를 보면 아직 웹소켓 연결이 안된다." (스크린샷 첨부)
- **스크린샷 타임스탬프 실측 정밀 원인 분석 팩트:**
  1. 폐하께서 보내주신 스크린샷 로그의 모든 시각이 정확히 `[03:45:30]` 동일 시각에 몰려 있는 팩트를 발견하였습니다.
  2. **원인 (소켓 미연결 시점 부팅 동기화 호출 타이밍 결함):** 클라이언트 구동 시 `ShinseonDashboard.__init__` 함수 내부에서 `run_startup_sync_sequence`가 실행되면서 `do_sync_balances()`를 호출하고 있었습니다.
  3. **순서 엉킴 팩트:** 하지만 이 시점은 웹소켓(`connect_websocket()`)이 AWS 서버에 **연결되기도 이전 시점**이므로 소켓이 당연히 없어 `⚠️ [웹소켓] 웹소켓 연결이 닫혔거나 재연결 중입니다.` 알림을 뱉고 동기화가 실패했던 것이었습니다.
  4. 이후 웹소켓이 서버에 정상 접속되었을 때는 정작 동기화 명령(`CMD_SYNC_POSITION`)을 보내주는 주체가 없어 잔고가 `$0.00 (실시간 동기화 대기)`에 머물렀던 치명적 순서 엉킴 맹점이었습니다.

###가. 부팅 동기화 위치 이관 수술 (`shinseon_client.pyw`)

2. **`connect_websocket()` 연결 수립 직후 동기화 배치:**

   - 서버와 소켓이 100% 정상 연결된 '그 즉시' 동기화 패킷을 보내므로, 부팅 시 단 1회의 에러도 없이 계좌 잔고($34.73)와 포지션 상태가 100% 즉시 연동됨.
