# [기획서 62] 50% 수동 청산 더블 프로텍션(Double Protection) 이중 이벤트 격발 전격 완공 수술 (V4.63)

## 1. 개요 및 팩트 원인 적출 (100% 실측 결과)
- **폐하의 지적:**
  "이거 클릭해도 아무런 반응이 없어"
- **소신의 100% 팩트 원인 적출 결과:**
  1. 클라이언트 `trigger_close_50` 메서드가 오직 `is_ws_active()` 조건 하에서만 WSS 패킷 전송을 시도하도록 작성되어 있었습니다.
  2. 비상 탈출(`emergency_close`) 버튼처럼 **WSS 패킷 전송 + 클라이언트 로컬 엔진 `v35_engine.execute_bitget_internal_packet` direct call 이중 격발 수식(Double Protection)**이 적용되어 있지 않아, WSS 상태 판정에 따라 클릭 시 로그 출력 없이 스킵될 위험이 있었습니다.

## 2. 상세 수술 및 배포 계획 (V4.63)

### 가. `trigger_close_50` 더블 프로텍션 수술 (`shinseon_client.pyw`)
- `trigger_close_50` 및 `trigger_stoploss_setting` 핸들러에 try-except 예외 로깅 보장 및 이중 격발 수식 반영:
  ```python
  def trigger_close_50(self):
      try:
          self.add_log("🌓 [수동 50% 청산] BITGET 포지션 50% 시장가 청산 명령 발동...")
          if hasattr(self, "bot_core") and self.bot_core and hasattr(self.bot_core, "v35_engine") and self.bot_core.v35_engine:
              self.bot_core.v35_engine.exit_reason = "수동 50% 분할 청산 명령 발동"
              # [더블 프로텍션] 백엔드 엔진 Direct Call 추가
              asyncio.create_task(self.bot_core.v35_engine.execute_bitget_internal_packet(side="CLEAR", order_type="50_PERCENT_CLOSE"))
          
          if self.is_ws_active():
              import json
              asyncio.create_task(self.ws.send(json.dumps({'cmd': 'CMD_CLOSE_50'})))
              self.add_log("📡 [서버 명령] CMD_CLOSE_50 (50% 시장가 청산) 패킷 전송 완료")
      except Exception as e:
          self.add_log(f"⚠️ [50% 청산 예외 발생]: {e}")
  ```
