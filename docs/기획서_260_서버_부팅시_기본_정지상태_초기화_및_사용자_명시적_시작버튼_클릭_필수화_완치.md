## 🎯 1. 개요 및 배경
- **현상 및 폐하의 답답함:**  
  > *"아 내가 자동봇 시작 안 눌렀는데 왜 자꾸 자동 봇 시작이 되어서 청산되냐 미치겠네"*
- **원인 정밀 규명 (100% 팩트 확인):**  
  1. 서버(`shinseon_server.py`)의 초기화 코드(라인 1629~1630)에 `self.bot_state = "RUNNING"`, `self.is_snipe_active = True`로 하드코딩되어 있어, **서버가 배포되거나 켜지는 즉시 클라이언트 버튼 조작 여부와 상관없이 백엔드에서 혼자 `RUNNING(가동 중)` 상태로 시작**되고 있었습니다.
  2. 반면 클라이언트 UI는 켤 때 버튼 텍스트가 `[ ▶ 자동 봇 시작 ]`으로 렌더링되어 있어, 폐하께서는 정지 상태인 줄 아셨으나 서버는 이미 신호를 감지하고 독단적으로 진입/청산을 집행하고 있었던 것입니다.
- **목적:**  
  서버 부팅 시 기본 상태를 **무조건 `bot_state = "STOPPED"` (정지 상태) 및 `is_snipe_active = False`로 완전 동결**하여, 폐하께서 클라이언트 대시보드에서 명시적으로 `[ ▶ 자동 봇 시작 ]` 버튼을 누르시기 전에는 절대로 어떠한 자동 진입이나 청산도 실행되지 않도록 완벽히 통제합니다.

## 🛠️ 2. 상세 작업 명세

### ① 서버 초기 부팅 상태 완전 정지(STOPPED)로 변경 (`shinseon_server.py` 라인 1629~1630)
```python
# [수정 전]: 서버가 혼자 RUNNING으로 켜짐
self.is_snipe_active = True
self.bot_state = "RUNNING"

# [수정 후 (V6.61 완치)]: 서버 부팅 시 무조건 STOPPED로 안전 동결!
self.is_snipe_active = False
self.bot_state = "STOPPED"
```

### ② 클라이언트 접속 및 동기화 시 정지 상태 100% 일치 보장 (`shinseon_server.py`, `shinseon_client.pyw`)
- 클라이언트 최초 접속 시 서버가 `bot_state: "STOPPED"`를 송신하고, 클라이언트 버튼도 `[ ▶ 자동 봇 시작 ]` 대기 상태로 완벽 일치.
- 오직 폐하께서 `[ ▶ 자동 봇 시작 ]`을 클릭하여 `CMD_START_BOT` 패킷을 전송할 때만 서버가 `RUNNING`으로 가동.
