# [기획서 46] 자동 봇 정지 시 AWS 서버 소켓 파기 결함 원천 수술 (V4.49)

## 1. 개요 및 트레이스 백 정밀 팩트 원인 분석
- **폐하의 지적 사항:**
  `▶ 자동 봇 정지` 버튼을 클릭했더니 웹소켓 연결이 닫히고 AWS 서버가 튕겨버리는 결함 발생 지적 (로그 제출)
- **소신의 정밀 트레이스 백 100% 팩트 원인 밝혀냄:**
  1. `CMD_STOP_BOT` 수신 시 `self.bot_core.execute_emergency()`를 호출하도록 설계되어 있었사옵니다.
  2. **원인 (메인 바이낸스 루프 소멸 맹점):**
     - `execute_emergency()` 내부 라인 818에 `self.current_task.cancel()` 구문이 들어있어서, 봇 정지 시 거래소 청산만 해야 하는데 **AWS 서버의 메인 텔레메트리 데이터 수집 태스크(`run_binance_websocket`) 자체를 취소(Cancel)시켜 서버 소켓을 내려버렸던 100% 팩트 원인**을 밝혀내었사옵니다!

## 2. 상세 수술 및 원천 복구 계획 (V4.49)

###가. `execute_emergency()` 메인 루프 파기 구문 적출 수술 (`shinseon_server.py`)
1. **`self.current_task.cancel()` 완전 적출:**
   - 자동 봇 정지 시 `bot_state = "STOPPED"`로 전환하여 신규 진입만 안전하게 멈추고, 서버의 메인 통신선 태스크(`current_task`)는 절대로 파기되지 않도록 원천 보호 수술을 집행합니다.
2. **봇 정지 ↔ 웹소켓 연속성 100% 보장:**
   - 봇을 정지하더라도 웹소켓 통신선이 튕기거나 끊기지 않고 100% 실시간 연동이 유지됩니다.

###나. 소신(안티그래비티) 직접 수술 및 배포
1. 버전을 `V4.49`로 지정.
2. 소신이 직접 소스코드 태스크 파기 결함 적출 수술 집행.
3. `deploy.py V4.49` 실행하여 Commit & GitHub main push.
4. AWS 서버 및 V4.49 대시보드 구동 후 자동 봇 정지 클릭 시 소켓 튕김 0건 100% 안착 최종 검증.
