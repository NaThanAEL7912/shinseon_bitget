# [기획서 47] 자동 봇 정지 시 포지션 유지 보호 및 비상 탈출 분리 수술 (V4.50)

## 1. 개요 및 트레이스 백 정밀 팩트 원인 분석
- **폐하의 지적 사항:**
  `▶ 자동 봇 정지`를 클릭했을 뿐인데 왜 비상 탈출 로직이 가동되는지 지적 (포지션 강제 청산 우려 지적 및 로그 제출)
- **소신의 정밀 트레이스 백 100% 팩트 원인 밝혀냄:**
  1. `shinseon_server.py` 라인 2180에서 `CMD_STOP_BOT` 수신 시 `await self.bot_core.execute_emergency()`를 호출하도록 묶여 있는 팩트를 발견하였습니다.
  2. **원인 (자동 봇 정지 ↔ 비상 탈출 혼용 맹점):**
     - 폐하께서는 신규 자동 저격 진입만 멈추고(`bot_state = "STOPPED"`) 기존 보유 중인 실전 포지션은 그대로 안전하게 유지하기 위해 '자동 봇 정지'를 누르신 것인데, 기존 코드가 '비상 탈출(`execute_emergency`)'을 묶어서 호출하고 있었던 치명적 맹점을 찾아내었습니다!

## 2. 상세 수술 및 원천 복구 계획 (V4.50)

###가. `CMD_STOP_BOT` 처리부 비상 탈출 연동 완전 제거 (`shinseon_server.py`)
1. **`CMD_STOP_BOT` (자동 봇 정지 클릭 시):**
   - 오직 `bot_state = "STOPPED"`로만 전환하여 **신규 자동 저격 진입만 멈추고, 이미 보유 중인 포지션은 100% 안전하게 그대로 유지**하도록 수술합니다.
   - 메시지 포맷 개편: `⏸ [봇 제어] 자동 저격 감시가 정지되었습니다 (보유 포지션 안전 유지)`
2. **`CMD_EMERGENCY` (우측 빨간색 `🚨 비상 탈출` 버튼 클릭 시):**
   - 오직 폐하께서 우측의 `🚨 비상 탈출 (EMERGENCY)` 버튼을 직접 누르셨을 때만 비상 탈출 로직(`execute_emergency()`)이 발동하여 포지션을 시장가 청산하도록 완벽히 기능 분리 수술합니다.
