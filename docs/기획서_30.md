# [기획서 30] 비트겟 API 비동기 태스크 분리 및 부팅 접속 성공률 100% 원천 복구 (V4.35)

## 1. 개요 및 팩트 분석
- **폐하의 지적 사항:**
  "아니 내가 계속 껏다 켯다 하니가 어떤때는 한번에 서버 촥 접속이 되어서 잘돌아가고 어떤 때는 또 안돌아가 5번 켰는데 1번만 제대로 돌아간다."
- **실측 정밀 원인 분석 팩트:**
  1. **서버 메시지 수신 루프 블로킹 팩트:** `shinseon_server.py`에서 `CMD_SYNC_POSITION` 명령을 받았을 때 `async for message in websocket:` 메인 루프 안에서 비트겟 API REST 호출(`fetch_balance`, `fetch_positions`)을 직접 `await` 하도록 구현되어 있었습니다.
  2. **1~2초 응답 지연 시 접속 간헐적 불량 발생:** 비트겟 해외 REST API 응답이 1~2초 지연되거나 네트워크 랙이 생기면, 웹소켓 수신 루프 전체가 대기 상태에 빠져 인증 및 초기 패킷 교환이 지연되고 클라이언트가 접속 불량/멈춤에 빠졌던 원인이었습니다. (5번 중 4번 간헐적 기동 실패 원인)

## 2. 상세 수술 및 원천 복구 계획 (V4.35)

###가. AWS 서버 비트겟 API 비동기 독자 태스크 분리 (`shinseon_server.py`)
1. **`asyncio.create_task` 독립 분리:**
   - `CMD_SYNC_POSITION` 요청 수신 시 메인 수신 루프를 차단하지 않고 `asyncio.create_task(self.handle_sync_position(websocket))`로 즉시 독립 비동기 태스크로 방출.
   - 메인 웹소켓 수신 루프는 0.001초도 멈추지 않고 100% 즉시 다음 메시지(`auth`, `ui_update`)를 지속 처리하여 부팅 접속 성공률을 100%로 끌어올림.
2. **소켓 직통 및 전역 브로드캐스트 2중 응답:**
   - 해당 클라이언트 소켓(`websocket.send`)과 전역 브로드캐스트(`broadcast_event`) 양쪽에 잔고/포지션 데이터를 지체 없이 전달.

###나. 클라이언트 부팅 순차 안정화 및 자가 치유 수술 (`shinseon_client.pyw`)
1. **부팅 명령 송신 순서 시차(0.3초) 부여:** 웹소켓 연결 성공 -> 인증(`auth`) 전송 -> 0.3초 후 `CMD_SYNC_POSITION` 전송으로 초기 패킷 엉킴 방지.
2. **잔고 동기화 미수신 시 3초 후 1회 자동 재조회 가드 탑재.**

###다. 버전 상향 및 배포 (`shinseon_client.pyw`, `shinseon_config.json`)
1. 버전을 `V4.35`로 지정.
2. `deploy.py V4.35` 실행하여 Commit & GitHub main push.
3. AWS 서버 업로드 및 재가동 후 5회 연속 껐다 켜기 테스트를 통한 부팅 접속 성공률 100% 최종 검증.
