# 기획서 216: CSV 레코더 1초 누락(Skip) 방지 및 정수 초(Integer Second) 100% 동기화 (V6.14)

## 📌 1. 개요 및 팩트 분석
- **현상:**  
  폐하께서 제보해 주신 CSV 장부 캡처 화면(`15:53:36` ➡️ `15:53:38` / `15:53:52` ➡️ `15:53:54`)과 같이, 신호가 바뀔 때나 소켓 틱이 밀릴 때 특정 1초가 중간에 1초씩 덤프 스킵(누락)되는 현상이 발생했습니다.
- **원인:**  
  `shinseon_server.py` L2242의 CSV 기록 트리거 조건문이 `elif current_time - self.last_record_time >= 1.0:` 부동소수점(float) 시간 차이 계산으로 되어 있었습니다.  
  틱 패킷이 0.98초 또는 0.99초 간격으로 미세하게 일찍 들어오면 `0.98초 < 1.0초` 조건에 걸려 해당 1초가 스킵되고 다음 초로 2초 jump(누락)하는 현상이 팩트로 포착되었습니다.
- **조치:**  
  시간 측정 방식을 부동소수점 차이에서 **정수 초(Integer Second: `int(current_time)`) 교체 방식**으로 전면 개편합니다.  
  매 정수 초가 변경될 때마다(`15:53:36` ➡️ `15:53:37` ➡️ `15:53:38`) 정확히 초당 1번씩 단 1초의 누락도 없이 100% 연속 누적되도록 완벽 수정합니다.

## 🛠️ 2. 작업 상세 내역
1. **`shinseon_server.py` L2236~L2245 레코딩 조건문 개편:**
   - 기존: `elif current_time - self.last_record_time >= 1.0:`
   - 수정: `current_second = int(current_time)` 기반 `if getattr(self, "last_record_second", 0) != current_second:`
2. **효과:**  
   신호 변동이나 소켓 패킷 유입 타이밍과 무관하게 매초 정각 1초 간격으로 100% 틈새 없는 영구 1초 고밀도 기록 보장.
