# 🚀 신선 비트겟 HFT(초단타) 분산 아키텍처 마스터 로드맵

폐하께서 하명하신 5단계 그랜드 마스터플랜을 구체화한 문서이옵니다. 이 로드맵에 따라 봇의 완전한 각성(Awakening)을 이룩하겠습니다.

## 1. AWS 일본 서버 임대 (인프라 구축)
- [ ] AWS 계정 생성 및 도쿄 리전(ap-northeast-1) 접속
- [ ] `t3.micro` 리눅스 서버 3대를 서로 다른 가용 영역(AZ)에 생성
- [ ] 1년 프리티어 및 요금 폭탄 방지 알람 설정

## 2. 핑(Ping) 테스트 및 서버 확정 (AZ-Hopping)
- [ ] 3대의 리눅스 서버에 각각 SSH(원격) 접속
- [ ] `ping fstream.binance.com` 명령어 실행
- [ ] 지연율(Latency)이 0.x ~ 2ms 이내로 가장 빠른 건물(AZ) 1대 선정
- [ ] 가장 빠른 1대를 제외한 나머지 2대 서버 즉시 삭제(과금 방지)

## 3. 분산 개발 (프론트/백엔드 해체 및 통신)
- [ ] **백엔드(엔진) 개발**: `shinseon_server.py` 생성. UI 코드를 날려버리고, 바이낸스 진짜 선물 WSS에 연결하여 0.001초 단위 체결 로직 이식. 웹소켓 서버(8765 포트) 개방.
- [ ] **프론트엔드(GUI) 개발**: `shinseon_client.pyw` 생성. 기존 매매 엔진 코드를 걷어내고, AWS 서버 IP로 웹소켓 통신을 걸어 차트와 로그만 받아오는 경량 모니터로 개조.
- [ ] 로컬 PC ↔ AWS 일본 서버 간의 암호화(Secret Token) 통신 검증.

## 4. 고도화 (최적화 및 신규 기능)
- [ ] 분산 아키텍처 환경에 맞춘 HFT 알고리즘 정밀도 튜닝 (로컬 레이턴시 변수 등 제거)
- [ ] 서버 콘솔 터미널에 CUI(Text-based UI) 형태의 매매 현황 미니 로거 추가
- [ ] 클라이언트와 서버 간 접속이 끊어졌을 때의 자동 재연결(Auto-reconnect) 로직 고도화

## 5. 안정화 (실전 가동 및 무중단 요새화)
- [ ] AWS 서버 재부팅 시에도 `shinseon_server.py`가 자동으로 실행되도록 `systemd` 서비스 등록.
- [ ] 메모리 누수(Memory Leak) 모니터링 및 24/7 가동 테스트
- [ ] 폐하의 로컬 모니터(GUI)를 끄고 출근하셔도 일본에서 완벽하게 돈을 복사하는지 최종 검증
