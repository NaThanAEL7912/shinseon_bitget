# ShinSeon Bitget 기획서_127 (server.log 이중 로깅 완전 제거, 실시간 새로고침 버튼 연동 복원기 및 수집 범위 명세서)

## 📌 개요
폐하의 지시에 따라 **중복 기재되던 `server.log` 파일 생성을 완전 제거**하고, **일별 로그 파일(`logs/shinseon_trade_YYYY-MM-DD.log`) 1곳으로 단권화**하여 서버 용량 폭증을 차단합니다. 또한 비트겟 체결 복원기를 클라이언트 연동 시가 아닌 **팝업창 `[🔄 실시간 새로고침]` 버튼 클릭 시에만 수동 격발**되도록 변경하고 **최근 7일치(최대 100건) 체결 이력 수집 범위**를 명확히 세팅합니다.

---

## 🎯 3대 정밀 수술 및 범위 명세

### 1. 🗑️ `server.log` 중복 로깅 완전 제거 & 일별 로그 단권화
- 기존 `server.log` 파일로 이중 작성되던 로깅 구문 및 리다이렉션을 완전 제거.
- 모든 서버 감시/체결/오류 로그는 오직 **`logs/shinseon_trade_YYYY-MM-DD.log` 일별 파일 1곳**에만 정격 기재되도록 수술하여 파일 비대화 및 처리 지연을 100% 원천 방지.

### 2. 🔄 `[실시간 새로고침]` 버튼 클릭 시에만 복원기 격발
- 서버 구동 시 및 클라이언트 자동 접속 시의 복원기 자동 가동 로직 전면 삭제.
- 폐하께서 누적 상세 보고서 팝업창에서 **`[🔄 실시간 새로고침]` 버튼을 직접 클릭하셨을 때에만** 서버에 `CMD_REQ_STATS_SYNC_RECOVERY` 패킷이 전송되어 복원기가 가동되도록 변경.

### 3. 📏 복원기 데이터 수집 범위 명세 (최근 7일 / 100건)
- **수집 범위:** 비트겟 선물 API (`fetch_my_trades(symbol='BTC/USDT:USDT', limit=100)`)를 활용하여 **최근 7일 이내 체결된 최대 100건의 체결/청산 이력**을 수집.
- **처리 방식:** 오늘 및 최근 7일 일별 통계 파일(`logs/trade_stats_YYYY-MM-DD.json`)을 대조하여, 누락된 체결 짝만 쏙 짚어내어 100% 깔끔하게 복원 갱신.
