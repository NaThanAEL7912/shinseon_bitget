## 1. 🎯 [기획 배경 및 문제 원인 정밀 분석]

### 1) 현상
- 폐하께서 모바일 비트겟 앱에서 `0.0176 BTC LONG` @ `$78,847.8` 주문을 수동으로 넣으셨으나, 거래소에 손절(SL)과 익절(TP) 라인이 자동으로 걸리지 않음.

### 2) 팩트 원인 분석
- [`shinseon_server.py`](file:///C:/Working/ShinSeon_Bitget/shinseon_server.py) 메인 서버는 24시간 백그라운드로 3초마다 `self.wss.sync_bitget_real_position_status()`를 호출함.
- 그러나 `WsServer` 내부에는 `self.bitget_exchange`가 존재하지 않고 오직 **`self.bot_core.bitget_exchange`**에만 API 인스턴스가 존재함.
- 이로 인해 `WsServer.sync_bitget_real_position_status()` 진입 시 `getattr(self, "bitget_exchange", None)` 조건문이 `None`으로 평가되어 **3초 상시 감시 루프가 거래소 조회를 건너뛰고 침묵**함.
- 따라서 사용자가 클라이언트 GUI에서 명시적으로 동기화 버튼을 누르기 전까지는 백그라운드에서 수동 포지션을 자동 포착하지 못했던 것임.

## 2. 🔍 [정공법 완치 설계]

1. **상시 동기화 루프 바인딩 단일화 & 직결:**
   - 3초 주기 상시 감시 루프(`run_telemetry_loop`)에서 중복된 `self.wss.sync_bitget_real_position_status()` 대신, 실제 API 인스턴스와 CCXT가 바인딩된 **`self.sync_bitget_real_position_status()` (BotCore 직속)**를 다이렉트 호출하도록 수정.
   - `WsServer` 내부의 `sync_bitget_real_position_status` 역시 `self.bot_core.bitget_exchange`를 올바르게 바라보도록 완전 정비.
2. **거래소 동기화 즉시 3대 안전 가드 자동 격발 보장:**
   - 휴대폰으로 주문 체결 후 최대 3초 이내에 서버가 거래소 실시간 포지션을 자동 감지하고,
   - 기존 미체결 주문 100% 캔슬 후 **1차 TP (50%), 2차 TP (50%), SL (100%)**를 거래소에 즉각 자동 발주.
3. **AWS 도쿄 실전 서버 배포 및 실계좌 즉각 검증:**
   - 버전을 **V7.35**로 상향.
   - 현재 폐하께서 휴대폰으로 진입하신 `0.0176 BTC LONG` 포지션에 3대 안전 가드가 정상 배치되었음을 확인하였으며, 향후 상시 24시간 3초 백그라운드 자동 발주가 100% 무결하게 작동하도록 AWS 서버에 즉시 배포.
