## 📌 1. 원인 파악 및 팩트 분석 (-0.1% 손절 미발동의 결정적 수학적 함정)

폐하께서 보내주신 스크린샷(ROE -1.38%, 오프셋 -0.10%)과 AWS 실시간 서버 로그(`shinseon_server.log`)를 1:1로 추적한 결과, **-0.10% 하방 손절 설정 후 ROE가 -1.38%로 떨어졌음에도 청산이 안 되었던 결정적 수학적 함정 팩트**를 찾아내었습니다!

### 🔍 팩트 원인 분석:
```python
# V5.72에 있던 조건식
if offset_val < pnl_at_set and offset_val <= live_roe_rounded:
    is_triggered = (live_roe_rounded <= offset_val) # 하방 손절
else:
    is_triggered = (live_roe_rounded >= offset_val) # 상방 익절
```

1. **`and offset_val <= live_roe_rounded` 가드 구문의 역설적 논리 오류 (결정적 진범):**
   - 폐하께서 ROE `0.00%` 시점에 손절 오프셋 `-0.10%`를 설정하셨습니다. (`pnl_at_set = 0.00%`, `offset_val = -0.10%`).
   - 비트코인 가격이 하락하여 실시간 ROE가 `-1.38%`가 되었을 때, 위 `if` 조건문을 검증하였습니다:
     - `offset_val < pnl_at_set` (`-0.10 < 0.00`) ➡️ **참(True)**
     - `offset_val <= live_roe_rounded` (`-0.10 <= -1.38`) ➡️ **거짓(False! -0.10이 -1.38보다 큼)**
   - 두 조건 중 두 번째 조건이 **거짓(False)**이 되는 바람에 `if` 문을 탈출하고 `else` (상방 익절 모드)로 건너뛰어 버렸습니다!
2. **`else` 블록에서의 청산 기각:**
   - `else` 블록으로 넘어간 서버는 `is_triggered = (live_roe_rounded >= offset_val)` (`-1.38 >= -0.10`)을 계산하였고, 당연히 거짓이 되어 청산이 기각되었습니다.
   - 결과적으로 ROE가 -0.10% 이하(-1.38%)로 떨어졌음에도 양쪽 조건문 모두 거짓이 되어 **청산 코드가 구동되지 못하고 갇혀버렸던 팩트**였습니다!

## 🛠️ 2. 정공법 완치 수술 상세 내역

### 2.1. 수학적 2분법 모드 분기 정화 (`shinseon_server.py`)
오프셋 설정 시점의 ROE(`pnl_at_set`) 대비 오프셋(`offset_val`)의 크기만으로 깔끔하게 2분법 분류하여 100% 예외 없이 발동하도록 수식을 완치합니다:

```python
if offset_val < pnl_at_set:
    # 1. 설정 오프셋이 설정 시점 ROE보다 이하인 경우 ➡️ 하방 수익보존/손절 모드
    is_triggered = (live_roe_rounded <= offset_val)
    cond_str = "이하"
    stop_label = "수익보존/손절"
else:
    # 2. 설정 오프셋이 설정 시점 ROE보다 이상인 경우 ➡️ 상방 목표익절/반등 모드
    is_triggered = (live_roe_rounded >= offset_val)
    cond_str = "이상"
    stop_label = "상승/반등익절"
```

### 🔍 3가지 실전 시나리오 100% 검증:
1. **[시나리오 1] ROE 0.00% 시점에 -0.10% 손절 설정:**
   - `-0.10 < 0.00` ➡️ 하방 손절 모드 지정 ➡️ `live_roe_rounded <= -0.10`
   - ROE가 -0.10%, -0.15%, -1.38% 도달 시 **100% 즉시 청산 발주!**
2. **[시나리오 2] ROE 0.00% 시점에 +0.30% 익절 설정:**
   - `+0.30 >= 0.00` ➡️ 상방 익절 모드 지정 ➡️ `live_roe_rounded >= +0.30`
   - 0.00% 조기 청산 없이 실제 ROE가 +0.30% 이상 올라갈 때까지 **100년이 걸려도 청산 대기!**
3. **[시나리오 3] ROE -1.90% 시점에 -1.80% 반등 익절 설정:**
   - `-1.80 >= -1.90` ➡️ 반등 익절 모드 지정 ➡️ `live_roe_rounded >= -1.80`
   - ROE가 -1.90% ➡️ -1.80% 반등 도달 시 **100% 반등 청산 발주!**
