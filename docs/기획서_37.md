# [기획서 37] 부팅 시 경고 로그 오발사 차단 및 웹소켓 자동 동기화 클린 복구 (V4.42)

## 1. 개요 및 로그 팩트 분석
- **폐하의 지적 사항:**
  `[04:17:06] [Websocket] 일본 AWS 릴레이 서버 연결 시도` 로그 이후 `[04:17:12] ⚠️ [웹소켓] 5회(2.5초) 대기 후에도 소켓 미연결 상태` 경고 로그가 발생하는 문제 (로그 제출)
- **정밀 트레이스 백 팩트 원인 분석:**
  1. 폐하께서 보내주신 부팅 로그를 정밀 추적한 결과, 부팅 직후 `load_shinseon_config()`에서 설정값을 로딩할 때 UI 컨트롤의 `textChanged` / `stateChanged` 시그널이 트리거되면서 소켓 연결 전 임의로 `send_config_to_server()`를 조기 호출하던 팩트를 발견하였습니다.
  2. **원인 (시그널 조기 트리거로 인한 가짜 경고로그 뿜음):**
     - 소켓이 연결 시도 중인 시점에 설정 파일 저장 시그널이 튀어 `send_config_to_server()`가 실행되고, 소켓이 아직 미연결 상태이므로 `⚠️ [웹소켓] 웹소켓 연결이 닫혔거나 재연결 중입니다.` 경고 로그를 조기에 연달아 뱉어 폐하께 혼선을 드렸던 근본 원인이었습니다.

## 2. 상세 수술 및 원천 복구 계획 (V4.42)

###가. 부팅 로딩 시 시그널 차단 및 미연결 시 조기 로그 억제 수술 (`shinseon_client.pyw`)
1. **`load_shinseon_config()` 시그널 바인딩 위치 교정:**
   - 설정값 로딩 시 UI 텍스트 변경 이벤트로 인해 `save_shinseon_config()`가 조기 격발되지 않도록 시그널 연결 순서를 로딩 이후로 배치.
2. **`send_config_to_server()` 조기 경고 억제:**
   - 소켓 미연결 상태일 때는 부팅 초기 조기 팝업 경고 로그를 뱉지 않도록 조용히 리턴 처리.
3. **웹소켓 100% 연결 완료 시점에만 단 1회 설정 수송:**
   - 소켓 접속(`async with websockets.connect`) 수립 직후 `auth` ➔ `send_config_to_server()` ➔ `CMD_SYNC_POSITION` 순서로 깔끔하게 100% 자동 동기화 집행.
