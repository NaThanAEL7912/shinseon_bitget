# [기획서 25] 웹소켓 동기화 전송 결함 원천 수술 및 잔고/포지션 즉시 동기화 완전 복구 (V4.30)

## 1. 개요 및 원인 정밀 분석
- **폐하의 지적 사항:**
  "로그 바바 계좌 동기화도 안되고 포지션 동기화도 또 안되냐"
- **원인 정밀 추적 팩트:**
  1. 클라이언트에서 `[실전 계좌 잔고 동기화]` 및 `[포지션 동기화]` 클릭 시 서버로 `CMD_SYNC_POSITION` 패킷을 정상 전송함.
  2. 서버(`shinseon_server.py`)의 `broadcast_event` 함수가 이벤트 패킷(`EVT_SYNC_BALANCE`, `EVT_SYNC_POSITION`)을 송신할 때 `asyncio.create_task(client.send(msg))` 형태로 비동기 방출을 수행하였으나, 기존에 연결 끊긴 폐기 웹소켓 객체(Dead Sockets)들이 정리되지 않은 채 누적되어 있던 게 원인이었음.
  3. 이로 인해 `EVT_SYNC_BALANCE` 및 `EVT_SYNC_POSITION` 응답 패킷이 유효한 클라이언트 스트림으로 즉시 전달되지 못하고 수신 차단되는 결함이 발생함.
  4. 또한 `CMD_SYNC_POSITION` 내 예외 처리 구문이 단순 `print()`로 처리되어 있어 에러 발생 시 로그 확인 및 예외 메시지가 클라이언트로 전달되지 않던 맹점이 확인됨.

## 2. 상세 수정 및 수술 계획

###가. AWS 서버 웹소켓 브로드캐스트 및 동기화 루틴 원천 수술 (`shinseon_server.py`)
1. **`broadcast_event` 및 `broadcast_throttled` 즉시 송신 & 폐기 커넥션 자동 정돈 고도화:**
   - 비동기 태스크 방출 대신 `await client.send(msg)`로 즉시 직접 전송.
   - 송신 실패한 폐기 소켓(Dead Socket)을 실시간으로 감지하여 `self.clients` 세트에서 무결하게 즉시 즉각 제거(Prune).
2. **`CMD_SYNC_POSITION` 로깅 및 에러 반환 탑재:**
   - 명령 수신, 비트겟 API 조회 결과(`usdt_total`, `active_pos`), 송신 상태를 `logger.info()`로 정밀 기록.
   - 비트겟 API 조회 중 예외 발생 시 `EVT_SYNC_ERROR` 이벤트 패킷을 클라이언트로 즉시 송신하여 클라이언트 화면에 상세 사유 표출.

###나. 클라이언트 대시보드 버전 및 UI 수응 확인 (`shinseon_client.pyw`, `shinseon_config.json`)
1. 버전을 `V4.30`으로 상향 지정.
2. 부팅 및 동기화 버튼 클릭 시 `$34.73` 잔고 및 포지션 상세 정보가 100% 즉시 반영됨을 확인.

###다. 배포 및 검증
1. `deploy.py V4.30` 실행하여 Commit 및 GitHub main push.
2. `shinseon_server.py`를 AWS 서버(`13.192.187.244`)에 업로드 및 재가동.
3. AWS `server.log`에서 `CMD_SYNC_POSITION` 동기화 로그 확인 및 클라이언트 대시보드 잔고/포지션 100% 동기화 최종 검증.
