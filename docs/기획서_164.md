## 🏛️ 2. 백서 신규 구성 목차 (HTML 구조)

### 2.1. 프로젝트 개요 및 목표
* **신선 프로젝트란?** 
  * 바이낸스 선물의 세력 청산 데이터와 미결제약정(OI) 속도를 초저지연으로 분석하여 비트겟 거래소에 0.1초 내외로 시장가 타점을 꽂아넣는 초고속 오더플로우 융합 자동 트레이딩 시스템.
* **목표:** 개미들의 손절/청산 물량과 세력의 신규 자금 유입을 포착하여 무손실에 가까운 최적의 타점을 선점하는 것.

### 2.2. 시스템 아키텍처 및 환경
* **서버 (AWS Ubuntu):** 
  * 바이낸스 WSS(Websocket) 연결, 1초 단위 듀얼 샘플링, 신호 분석, 텔레그램 연동, 비트겟 실전 발주(`shinseon_server.py`, `core_logic.py`).
* **클라이언트 (Local Windows):** 
  * PySide6 기반 UI 대시보드. AWS 서버와 TCP/IP 통신하여 실시간 로그와 시세 차트를 전시(`shinseon_client.pyw`).
* **거래소 연동:**
  * **Binance:** 데이터 수집용 (WebSocket API)
  * **Bitget:** 실전 발주용 (REST API v2)

### 2.3. 핵심 코어 엔진 (V5.62 황금 전성기 룰)
* **0단계 듀얼 임계치 전제:** `청산금액 >= target_liq` AND `abs(OI속도) >= target_oi`
* **1단계 방향성 4대 매트릭스:** (Case A, B, C, D 상세 설명 및 세력 메커니즘 팩트)
* **2단계 반대 청산 및 스위칭 로직:** 60초 안전 락다운, 가짜 찌꺼기 무시(`oi_delta < 0`), 진짜 자금 유입 시 스위칭(`oi_delta > 0`).

### 2.4. 모든 기능 상세 명세 (What, Why, How)
* **스마트 수량 가드 (최소 발주 방어):** 50% 분할 시 0.0001 BTC 미만이 되면 전량 청산으로 안전하게 치환. (400172 에러 방지)
* **지능형 가드레일 (본전 가드 / 피크 트레일링):** 왜 만들었으며 어떻게 설정하고 작동하는지.
* **눌림목 불타기 (Pyramiding):** 수익 극대화를 위해 1차 익절 후 동일 추세 시 30% 추가 진입.
* **비상 마스터 탈출:** API 오류 시 0.5초 만에 재격발하여 무조건 포지션을 청산하는 궁극의 안전장치.
* **텔레그램 이중 양방향 제어:** AWS 서버 독점 관리 및 12대 알림 시스템 통합.
* **초고밀도 CSV 레코더:** 평시 1분, 임계치 50% 돌파 시 1초 단위 딥다이브 로깅.

### 2.5. 폴더 및 핵심 파일 명세서
* `shinseon_server.py`: AWS 메인 데몬. 바이낸스 WSS 통신 및 실전 API 패킷 직송.
* `core_logic.py`: 서버와 클라이언트 양측의 보조 연산, 설정 관리, UI 콜백, 트레일링/쿨타임 백그라운드 태스크.
* `shinseon_client.pyw`: 로컬 Windows UI (PySide6).
* `deploy.py` / `shinseon_updater.py`: 자동 버전 업 및 깃허브 배포 엔진.
* `docs/SHINSEON_오더플로우_판단_백서.md`: 🚨 **절대 수정 불가 핵심 대헌법**.

### 2.6. 🛠️ 트러블슈팅 및 유지보수 가이드 (개발자 매뉴얼)
* **증상 1: 비트겟 주문이 안 나갈 때 (API 에러)** ➡️ `shinseon_server.py`의 `execute_bitget_internal_packet` 라인 점검.
* **증상 2: 오더플로우 깃발 방향이 이상할 때** ➡️ `shinseon_server.py`의 `price_delta_1m` 및 `oi_delta_1m` 산출식과 4대 매트릭스 점검.
* **증상 3: 클라이언트-서버 연결 끊김 현상** ➡️ `shinseon_server.py`의 `start_socket_server` 및 클라이언트 TCP 재연결 로직 점검.
* **증상 4: CSV 기록이 누락될 때** ➡️ `core_logic.py`의 `check_radar_signal_dynamic` 내부 `_write_csv` 태스크 점검.
