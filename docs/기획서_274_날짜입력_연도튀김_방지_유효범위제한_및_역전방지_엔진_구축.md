# 기획서 274: 날짜 입력 시 2027년 연도 튐 방지 유효 범위 제한 및 시작/종료 역전 방지 엔진 구축

## 1. 개요 및 배경
- 폐하의 질문: "데이터가 왜 없다고 나오지?"
- 원인 정밀 진단 팩트 보고:
  - 폐하께서 올려주신 스크린샷의 상단 시작 일시를 보시면 **`2027-08-18` (2027년!)** 로 입력되어 있습니다.
  - 종료 일시는 `2026-08-21` (2026년)로 되어 있어, **시작 일시가 종료 일시보다 1년이나 앞선 미래(2027년)로 역전**되어 데이터 검색 결과가 0건이 되어 "데이터 틱이 없습니다" 오류가 발생하였음.
  - 원인: 날짜 입력 위젯에 유효 범위 제한(Range Lock)이 걸려있지 않아 키보드 입력이나 화살표 조작 시 연도가 2026년에서 2027년으로 튀어버렸음.

---

## 2. 세부 개발 계획

### 1) 🔒 날짜 입력 위젯 유효 범위 락 (Range Lock) 탑재
- `dt_start`와 `dt_end`에 실측 데이터 가용 범위(`2026-08-01 00:00:00 ~ 2026-08-31 23:59:59`)로 **`setDateTimeRange()`를 엄격히 제한**.
- 키보드로 입력하거나 화살표를 누르더라도 **절대로 2027년이나 2025년 등 데이터가 없는 엉뚱한 연도로 튀지 않도록 원천 봉쇄**.

### 2) 🛡️ 시작 일시 > 종료 일시 역전 방지 자동 보정
- 시작 일시가 종료 일시보다 늦게 설정되는 경우:
  - 자동으로 종료 일시를 시작 일시 당일 `23:59:59` 또는 그 이후로 즉각 동기화하여 역전 오류 원천 차단.
