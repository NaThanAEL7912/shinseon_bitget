# [기획서 34] 소켓 재연결 시 자동 동기화 보호막 이식 및 수동 동기화 자동 재시도 원천 복구 (V4.39)

## 1. 개요 및 로그 팩트 분석
- **폐하의 지적 사항:**
  `[03:59:35] [자산 조회] 실계좌 실시간 자본 동기화 개시...`
  `[03:59:35] [뷰어 모드] 잔고 동기화 명령을 서버로 전송합니다.`
  `[03:59:35] ⚠️ [웹소켓] 웹소켓 연결이 닫혔거나 재연결 중입니다.`
- **정밀 트레이스 백 팩트 분석:**
  1. 폐하께서 버튼을 누르신 03:59:35~38 시점은 웹소켓 접속이 일시적인 3초 재연결 대기 루프(`await asyncio.sleep(3)`) 구간에 진입해 있어 `self.ws`가 `None` 상태였던 팩트를 확인하였습니다.
  2. 기존 코드에서는 `self.is_ws_active()`가 `False`일 때 단순 경고 로그만 뱉고 동기화를 포기해 버려, 폐하께서 버튼을 계속 누르셔도 재연결이 끝날 때까지 잔고가 연동되지 않고 경고만 떴던 치명적 맹점이 있었습니다.

## 2. 상세 수술 및 원천 복구 계획 (V4.39)

###가. 수동 동기화 자동 연결 대기/재시도 보호막 이식 (`shinseon_client.pyw`)
1. **`do_sync_balances()` 및 `do_position_sync()` 수술:**
   - 버튼을 눌렀을 때 소켓이 잠시 재연결 중(`is_ws_active() == False`)이면, 포기하지 않고 **최대 2.5초간 소켓 재연결을 대기(Wait for reconnect)한 후 소켓이 뚫리는 즉시 `CMD_SYNC_POSITION`을 전송**하도록 자동 재시도 락 이식.
   - 소켓이 끊겨 있더라도 즉시 백그라운드 재연결(`connect_websocket()`)을 살려내어 1~2초 내로 잔고가 100% 무조건 동기화됨.

###나. 웹소켓 재접속 완료 시 무조건 자동 동기화 구동 (`connect_websocket`)
1. **재연결 성공 시 무조건 즉시 동기화 연동:**
   - 네트워크 변동 등으로 웹소켓이 재연결될 때마다 `self.ws.send("CMD_SYNC_POSITION")`을 자동 방출하여, 폐하께서 버튼을 누르지 않으셔도 잔고($34.73)와 포지션이 100% 자동 유지되도록 강화.

###다. 중복 구동 프로세스 완벽 정리
1. 백그라운드에 남아 있는 이전 버전 `pythonw.exe` 프로세스를 100% 강제 종료하여 중복 소켓 충돌을 원천 차단.

###라. 버전 상향 및 배포 (`shinseon_client.pyw`, `shinseon_config.json`)
