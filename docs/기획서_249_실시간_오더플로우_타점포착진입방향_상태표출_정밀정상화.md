# 📋 기획서 249: 실시간 오더플로우 [타점 포착 시 진입 방향] 표출 로직 정밀 정상화 기획서

---

## 🎯 1. 개요 및 배경
- **현상 및 문제점:**  
  대시보드 메인 화면의 `[ 타점 포착 시 진입 ]` 상태 라벨에서, 조건 미충족 상태(1분 OI 음수 `-0.0372%` 또는 추세 혼조세)이거나 실전 포지션을 이미 보유 중임에도 불구하고 클라이언트 기본 `else` 분기 처리에 의해 **`[ 타점 포착 시 진입: SHORT 🔴 ]`이 부자연스럽게 상시 고정 표출**되는 오류가 발생하고 있었습니다.
- **목적:**  
  백서의 헌법 원칙(순수 +OI 유입, EMA 추세, 청산 주도성) 및 실시간 포지션 보유 상태에 100% 정합하도록 **실시간 타점 포착 힌트 라벨 표출 엔진을 정밀 수술**합니다.

---

## 🛠️ 2. 상세 작업 명세

### ① 서버 텔레메트리 `expected_dir` 상태 분기 정밀화 (`shinseon_server.py`)
1. **포지션 보유 상태 분기:**
   - 엔진이 포지션을 보유 중(`is_position_active == True`)일 때:  
     `expected_dir = "HOLD_LONG"` 또는 `"HOLD_SHORT"` 송출.
2. **포지션 미보유 상태 분기 (백서 V6.25 정통 돌파 규칙):**
   - `EMA기울기 > 0` and `OI속도 > 0` and `숏청산 >= 롱청산` ➔ `expected_dir = "LONG"`
   - `EMA기울기 < 0` and `OI속도 > 0` and `롱청산 >= 숏청산` ➔ `expected_dir = "SHORT"`
   - 그 외(OI 음수, EMA/청산 불일치, 혼조세 등 조건 미충족) ➔ `expected_dir = None` (대기 상태)

---

### ② 클라이언트 힌트 라벨 3단 상태 시각화 수술 (`shinseon_client.pyw`)
1. **3대 상태별 정밀 렌더링:**
   - **`HOLD_LONG` / `HOLD_SHORT` (포지션 보유 중):**  
     `[ 🛡️ {LONG/SHORT} 포지션 보유 중 (가드레일 케어 가동) ]` (골드 & 에메랄드 테마)
   - **`LONG` / `SHORT` (타점 포착 실시간 유효):**  
     `[ 🟢 타점 포착 시 진입: LONG ]` / `[ 🔴 타점 포착 시 진입: SHORT ]` (그린/레드 발광 테마)
   - **`None` / 조건 미충족 (OI 음수 or 혼조세):**  
     `[ ⏳ 타점 탐색 대기 중 (조건 미충족) ]` (정갈한 다크 골드 대기 테마)
