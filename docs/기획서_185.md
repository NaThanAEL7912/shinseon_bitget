# 기획서 185: 비트겟 발주 딜레이(1.8초 ➡️ 0.05초) 초고속 플래시 직송 엔진 완치 수술

## 📌 1. 개요 및 원인 분석
- **현상 (00:01:03 신호 ➡️ 00:01:05 체결 2초 지연 현상):**
  - 00:01:03 KST에 타점이 터졌음에도 불구하고 실제 비트겟 체결까지 무려 약 1.8초~2초의 지연 시간이 발생했습니다.
- **소스코드 팩트 원인 검증 (`shinseon_server.py` L2107-L2165):**
  - 주문 1건을 쏠 때마다 `_execute_bitget_internal_packet_impl` 함수 내부에서 **3개의 HTTP REST 통신을 순차적으로 3번 연속** 날리고 있었습니다.
    1. 1차 통신: `POST /api/v2/mix/account/set-margin-mode` (격리 설정) ⏱️ ~0.6초
    2. 2차 통신: `POST /api/v2/mix/account/set-leverage` (레버리지 설정) ⏱️ ~0.6초
    3. 3차 통신: `POST /api/v2/mix/order/place-order` (실제 주문 발주) ⏱️ ~0.6초
  - 이로 인해 총 **$0.6\text{초} \times 3 = 1.8\text{초}$**의 심각한 네트워크 통신 딜레이가 매 진입마다 누적 발생했던 팩트를 확인했습니다.
- **목적:** 진입 시 사전 마진모드/레버리지 통신 2건을 완전히 제거(프로그램 기동 시 1회 사전 설정으로 전환)하고, 타점 발생 시 오직 **`place-order` 1개 패킷만 0.05초 만에 직송(Flash Send)**하여 딜레이를 1.8초에서 0.05초(50ms)로 36배 전격 단축시킵니다.
