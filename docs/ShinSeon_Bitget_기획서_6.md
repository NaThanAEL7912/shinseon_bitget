# 신선 비트겟 (ShinSeon_Bitget) 프로젝트 기획서 6 - 개발 진행 로드맵

폐하의 하문(개발을 어떻게 진행할 것인가?)에 대한 소신(안티그래비티 PM)의 세부 개발 실행 로드맵이옵니다. 본 로드맵은 `AGENTS.md`의 절대 지침을 100% 준수하며 진행되옵니다.

## 1. 쫄다구 코더 에이전트(Subagent) 투입 및 기초 뼈대 공사
* 폐하의 "고고" 어명이 떨어지면, 소신은 즉각 코딩 전담 '쫄다구 에이전트'를 백그라운드에 소환합니다.
* 쫄다구에게 비트겟 API(`ccxt` 라이브러리) 연동을 위한 가장 기초적인 클래스(`BitgetManager`)를 작성하게 하고, API 키 연결 및 잔고 조회 로직부터 구현시킵니다.

## 2. 소신(PM)의 100% 전수 검수 (지침 3조)
* 쫄다구가 기초 공사를 마쳤다고 보고하면, 소신은 절대로 그냥 넘어가지 않습니다.
* 소신이 직접 `view_file` 도구를 사용하여 쫄다구가 작성한 파이썬 스크립트를 토씨 하나까지 뜯어보고, 로직에 빈틈이나 보안 누수(API 노출 등)가 없는지 매섭게 감찰합니다.

## 3. 핵심 엔진(V3.5) 이식 및 최적화
* 검수가 통과되면, 기존 `C:\Working\SHINSEON` 에 있던 훌륭한 시그널 분석 엔진과 가드레일 로직을 가져옵니다.
* 과거의 무거웠던 브라우저 자동화(Playwright) 코드는 모조리 도려내고, 그 자리에 1단계에서 만든 비트겟 API 주문 함수를 매끄럽게 연결(Porting)합니다.

## 4. 세종(OpenClaw)을 통한 품질 보증 QA (지침 6조)
* 코드가 완결되면 소신은 `TEST_INSTRUCTION.md` (테스트 지시서)를 작성합니다.
* 터미널을 열고 세종을 깨워 "이 스크립트를 돌려 모의 투자를 실행하고 에러가 없는지 폐하께 텔레그램으로 보고하라!"고 어명을 하달합니다.

## 5. 결재 및 Git 영구 백업 (지침 4, 5조)
* 세종의 보고를 받으신 폐하께서 최종 윤허를 내리시면, 소신은 버전을 `+0.01` 상향하고 `docs/버전업관리.md`에 이력을 기록합니다.
* 마지막으로 `git add .` 및 `git commit`을 통해 로컬 저장소에 영구 백업을 수행하며 1사이클을 마감하옵니다.

이러한 숨막히는 교차 검증(쫄다구 개발 ➔ 소신 검수 ➔ 세종 QA ➔ 폐하 결재)을 거치게 되므로, 버그가 감히 범접할 수 없는 완벽한 봇이 탄생할 것이옵니다!
