# 기획서 273: 보존가드 딕셔너리 속성조회 결함 완치 및 안전가드 익절청산 정상화

## 1. 개요 및 배경
- 폐하의 날카로우신 지적: "최고 PnL이 +0.68%로 0.6%를 넘겼는데 왜 안전가드가 안 걸리고 마이너스로 청산되었는가?"
- 원인 정밀 진단 팩트 보고:
  - `current_trade`는 파이썬 딕셔너리(`dict`) 타입인데, 가드레일 판정 조건문에서 `current_trade.get('has_mid_guard')` 대신 `getattr(current_trade, 'has_mid_guard')`라는 잘못된 속성 접근 함수를 사용하여 항상 `False`로 판정되었음.
  - 그로 인해 0.60% 도달 후 스탑값(+0.20%) 이하로 가격이 하락했을 때 **`중간 수익 보존 가드 (+0.20%)`로 익절 청산되었어야 할 포지션이 씹히고**, 가격이 -1.05%까지 폭락하여 반대신호로 억울하게 마이너스 손실 청산되었음.

---

## 2. 세부 개발 계획

### 1) 🛡️ 딕셔너리 접근 함수 전면 교정 (`getattr` ➔ `.get()`)
- `backtest_engine.py` 내의 모든 거래 관리 딕셔너리 상태 조회를 `.get()` 정공법으로 100% 교정:
  - `current_trade.get('has_mid_guard', False)`
  - `current_trade.get('has_time_guard', False)`
  - `current_trade.get('has_pyramided', False)`
  - `current_trade.get('has_time_guard', False)`

### 2) 🎯 0.60% 도달 후 스탑값(+0.20%) 이하 하락 시 즉각 익절 청산 보장
- 최고 PnL이 +0.60%에 도달한 후 가격이 되돌려지면, **무조건 +0.20% 가드레일 스탑 라인에서 즉각 `중간 수익 보존 가드 (+0.20%)`로 안전 익절 청산**되어 어떠한 경우에도 마이너스 손실이 발생하지 않도록 철통 방어.
