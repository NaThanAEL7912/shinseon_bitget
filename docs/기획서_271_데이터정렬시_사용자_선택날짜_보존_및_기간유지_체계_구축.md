# 기획서 271: 데이터 정렬 시 사용자 선택 날짜 100% 보존 및 기간 유지 체계 구축

## 1. 개요 및 배경
- 폐하의 지엄하신 지적: "17일부터 21일까지 날짜를 선택하고 [데이터 정렬]을 클릭했는데, 선택한 날짜가 전체 기간(8/7 ~ 8/24)으로 다 풀려버렸다."
- 결함 원인:
  - `on_sync_data()` 완료 시 `self.dt_start`와 `self.dt_end`를 전체 원천 데이터의 최소/최대 일시(`min_dt`, `max_dt`)로 무조건 덮어쓰도록 코딩되어 있어, 폐하께서 정성껏 세팅하신 날짜(17일~21일)가 강제로 리셋되었음.

---

## 2. 세부 개발 계획

### 1) 🛡️ [데이터 정렬] 시 폐하의 선택 날짜 100% 철통 보존
- `on_sync_data()` 시작 시:
  - 폐하께서 현재 선택/입력해두신 시작 일시와 종료 일시(`cur_start_dt`, `cur_end_dt`)를 안전하게 기억.
- 정렬 완료 후:
  - 전체 원천 데이터(`min_dt ~ max_dt`)는 엔진 캐시로 완벽히 구축하되,
  - **상단 날짜 컨트롤러(`self.dt_start`, `self.dt_end`)는 폐하께서 지정하신 날짜(예: 17일~21일)를 1초의 변동도 없이 100% 그대로 유지·보존**.

### 2) 📊 완료 알림 및 즉시 백테스트 연동
- 정렬 완료 팝업 안내:
  - "총 24개 파일 실측 데이터 (1,096,490틱) 정렬 완료!"
  - "현재 선택 유지 구간: `YYYY-MM-DD ~ YYYY-MM-DD` (지정하신 구간으로 즉시 백테스트 가능)"
- 정렬 후 자동 백테스트 실행 시에도 폐하께서 선택하신 그 날짜 구간으로 즉시 시뮬레이션 수행.
