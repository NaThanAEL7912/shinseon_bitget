## 1. 배경 및 문제점 분석 (Root Cause Analysis)

### 1.1 현상
- ,547 롱 진입 후 목표가(,242)에 도달했을 때, **50%만 분할 익절되고 나머지 50%는 추가 폭등을 타야 했으나, 포지션이 100% 전량 일괄 청산**되어 버려 ,500+ 추가 랠리의 더블 수익 기회를 놓침.

### 1.2 원인 분석 (shinseon_server.py L1929)
- 비트겟 거래소에 TP/SL 플랜 주문을 전송할 때 planType 파라미터가 **pos_profit (전체 포지션 일괄 익절)** 로 하드코딩되어 전송되고 있었음.
- 이로 인해 비트겟 서버에서 수량(size) 지정을 무시하고 **포지션 전체(100%)를 한 번에 닫아버리는 문제**가 발생함.

---

## 2. 정공법 해결 설계 (Technical Solution)

### 2.1 비트겟 REST API place-tpsl-order 정격 분할 전환

| 구분 | 기존 방식 (pos_profit) | 신규 정공법 (profit_plan) |
|:---|:---|:---|
| **API planType** | pos_profit (전체 포지션 100% 일괄 청산) | **profit_plan (수량 지정 부분 분할 익절)** |
| **청산 수량 (size)** | 전체 100% 강제 청산 | **진입 수량의 정확히 50% (qty_btc * 0.5)** |
| **남은 50% 포지션** | 없음 (전량 종료) | **진입가 본전스탑(BEP) 걸고 무한 스윙 랠리 탑승!** |
| **비트겟 UI 표기** | Entire TP/SL | **Partial TP/SL (수량 분할 익절)** |

### 2.2 소스코드 수정 완료 내역 (shinseon_server.py L1925~1935)
