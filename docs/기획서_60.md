# [기획서 60] 비트겟 v2 API 청산 side 파라미터 정격 교정 및 50% 청산 원격 완공 수술 (V4.61)

## 1. 개요 및 팩트 원인 적출 (100% 실측 결과)
- **폐하의 지적:**
  "똑같이 안되는데?"
- **소신의 100% 팩트 원인 적출 결과:**
  1. 클라이언트 `🌓 50% 청산` 버튼 클릭 시 WSS 패킷 `CMD_CLOSE_50`이 AWS 서버로 정상 전송되었습니다.
  2. 그러나 AWS 서버의 기존 비트겟 v2 API 청산 수식에서, LONG 포지션 청산 시 `side` 파라미터가 CCXT 규격인 `sell`로 전송되어 비트겟 v2 API 엔진으로부터 `code: 22002 (No position to close)` 응답을 반환받으며 청산 주문이 거부되었습니다.
  3. 소신이 직접 비트겟 v2 REST API 실측 검증을 수행한 결과:
     - **LONG 포지션 청산 시:** `side: "buy"`, `tradeSide: "close"`, `holdSide: "long"` (응답: `code: 00000 success` 100% 정상 체결 실증 완료!)
     - **SHORT 포지션 청산 시:** `side: "sell"`, `tradeSide: "close"`, `holdSide: "short"`

## 2. 상세 수술 계획 (V4.61)

### 가. `_execute_bitget_internal_packet_impl` 비트겟 v2 REST API 청산 파라미터 교정 (`shinseon_server.py`)
1. `50_PERCENT_CLOSE` 및 `PARTIAL_CLOSE` 청산 발주 시, CCXT `create_order` 대신 100% 신뢰도가 입증된 **비트겟 v2 REST API `POST /api/v2/mix/order/place-order` 직송 수식**으로 전환합니다.
2. LONG 청산 시: `side: "buy"`, `tradeSide: "close"`, `holdSide: "long"`
3. SHORT 청산 시: `side: "sell"`, `tradeSide: "close"`, `holdSide: "short"`
4. 청산 수량(`size`)을 비트겟 최소 수량 단위(0.001 BTC)로 정밀 캘리브레이션하여 전송합니다.
