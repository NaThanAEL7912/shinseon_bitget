# ShinSeon Bitget 기획서_175 (스마트 스탑 버튼 조기 즉시 청산 팩트 원인 및 100% 완치안)

## 📌 1. 원인 파악 및 팩트 분석 (스마트 스탑 누르자마자 즉시 청산되는 진범)

폐하께서 첨부해 주신 대시보드 스크린샷과 18시 48분 38초, 18시 49분 28초의 AWS 서버 실시간 로그(`shinseon_server.log`)를 1:1로 정밀 추적한 결과, **스마트 스탑 설정 버튼을 누르자마자 0.001초 만에 즉시 청산되었던 100% 명백한 팩트 원인**을 밝혀내었습니다!

### 🔍 팩트 원인 분석:
```log
[18:49:25] [LONG 진입 @ 64,246.4] ROE: -0.00%
[18:49:28] 🌐 클라이언트 패킷 수신: CMD_SET_SMART_STOP (오프셋: +0.30%)
[18:49:28] 🛡️ [웹서버 스마트 스탑 청산 완료] 실시간 ROE(-0.00%)가 설정 오프셋(+0.30% ROE) 이하 도달! (100% 수익보존/손절 청산 완료)
```

1. **이전 포지션 진입가 잔재로 인한 `pnl_at_set` 오작동 (결정적 진범):**
   - 신규 포지션(LONG @ 64,246.4)이 진입했으나, `CMD_SET_SMART_STOP` 패킷 처리 시 `pnl_at_set`(설정 시점 ROE)을 계산할 때 **이전 직전 포지션의 구형 진입가(64,130.0) 잔재 수식**으로 연산되어 `pnl_at_set`이 `+5.44%`라는 거대한 양수로 잘못 측정되었습니다.
2. **모드 판정 오류 및 즉시 청산 격발:**
   - 서버는 폐하께서 입력하신 오프셋(`+0.30%`)과 잘못 계산된 설정시점 ROE(`+5.44%`)를 비교하였습니다.
   - `0.30% < 5.44%`이므로 서버는 이를 **"ROE가 +5.44%에서 +0.30% 이하로 떨어지면 청산하는 하방 손절/수익보존 모드(`live_roe <= 0.30%`)"**로 잘못 분류하였습니다.
   - 신규 포지션의 실시간 ROE는 `-0.00%`였으므로, 서버는 **"-0.00%는 +0.30% 이하가 맞다!"**고 단정짓고 **설정 버튼을 누르는 0.001초 순간에 즉시 시장가 청산을 발주**해버렸던 팩트였습니다!
