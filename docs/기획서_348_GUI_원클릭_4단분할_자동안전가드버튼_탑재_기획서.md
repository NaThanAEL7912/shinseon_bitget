## 2. 🔍 [정밀 설계 및 발주 메커니즘]

### 1) 4단 분할 안전가드(TP 2단 + SL 2단) 산출 공식

현재 실시간 포지션의 **평단가($E$)** 및 **총 계약 수량($V$)**, **방향($Side$)**을 실시간 조회하여 정밀 연산합니다:

#### 🟢 **LONG (롱 포지션)** 일 때:
- **수량 분할:**
  - 1차 수량: $V_1 = \text{round}(V \times 0.5, 4)$
  - 2차 수량: $V_2 = \text{round}(V - V_1, 4)$
- **🎯 1차 익절 (TP1 50%):** $E + 1000.0$ (수량: $V_1$, `profit_plan`)
- **🎯 2차 익절 (TP2 50%):** $E + 1200.0$ (수량: $V_2$, `profit_plan`)
- **🛡️ 1차 손절 (SL1 50%):** $E - 500.0$ (수량: $V_1$, `loss_plan`)
- **🛡️ 2차 손절 (SL2 50%):** $E - 600.0$ (수량: $V_2$, `loss_plan`)

#### 🔴 **SHORT (숏 포지션)** 일 때:
- **수량 분할:**
  - 1차 수량: $V_1 = \text{round}(V \times 0.5, 4)$
  - 2차 수량: $V_2 = \text{round}(V - V_1, 4)$
- **🎯 1차 익절 (TP1 50%):** $E - 1000.0$ (수량: $V_1$, `profit_plan`)
- **🎯 2차 익절 (TP2 50%):** $E - 1200.0$ (수량: $V_2$, `profit_plan`)
- **🛡️ 1차 손절 (SL1 50%):** $E + 500.0$ (수량: $V_1$, `loss_plan`)
- **🛡️ 2차 손절 (SL2 50%):** $E + 600.0$ (수량: $V_2$, `loss_plan`)

### 3) 서버사이드 집행 엔진 ([`shinseon_server.py`](file:///C:/Working/ShinSeon_Bitget/shinseon_server.py))

1. **`CMD_TRIGGER_AUTO_GUARD_4STAGE` 명령 수신 시:**
2. 비트겟 V2 REST API로 실시간 활성 포지션을 0.001초 만에 직접 조회.
3. 포지션이 없을 경우: 클라이언트에 `⚠️ [자동 안전가드] 현재 보유 중인 포지션이 없습니다.` 로그 브로드캐스트.
4. 포지션이 있을 경우:
   - 기존 대기 플랜 주문(구형 TP/SL)을 취소 정화.
   - 평단가 기준 TP1, TP2, SL1, SL2 4개 주문을 비트겟 V2 REST API(`/api/v2/mix/order/place-tpsl-order`)로 즉시 직송 발주!
   - 거래소 성공 응답(`code: 00000`) 확인 후 대시보드 및 텔레그램에 완료 보고 패킷 송신.
