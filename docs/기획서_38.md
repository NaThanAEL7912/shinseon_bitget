# [기획서 38] 중복 웹소켓 태스크 경쟁 상태(Race Condition) 100% 원천 소멸 및 단일 통신선 단권화 (V4.43)

## 1. 개요 및 트레이스 백 정밀 팩트 원인 분석
- **폐하의 지적 사항:**
  직접 만든 웹소켓인데 접속을 못 하고 5회 안착 대기 경고만 터지는 지경에 대한 폐하의 격노 (로그 제출)
- **소신의 정밀 트레이스 백 최후의 100% 팩트 원인 밝혀냄:**
  1. 소신이 코드를 1줄 1줄 전수 조율하며 추적한 결과, **동일한 웹소켓 접속 태스크(`connect_websocket()`)가 2개가 동시에 생성되어 서로 소켓 주도권을 뺏고 튕겨내는 치명적 경쟁 상태(Race Condition)**를 자행하고 있었던 진상을 밝혀내었습니다!
  2. **경쟁 상태 원인 팩트:**
     - 라인 3449: `dashboard.ws_task = loop.create_task(dashboard.connect_websocket())` (메인 진입점)
     - 라인 1886: `self.ws_task = asyncio.create_task(self.connect_websocket())` (부팅 시퀀스 내부)
     - 앱이 켜질 때 똑같은 소켓 루프 2개가 동시 가동되어, 태스크 1이 소켓을 뚫어놓으면 태스크 2가 동일 서버로 중복 접속하여 태스크 1 소켓을 강제 끊어버리고, 서로 `self.ws` 변수를 덮어쓰며 계속 접속을 무너뜨렸던 원인이었습니다!
