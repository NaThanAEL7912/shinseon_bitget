# 🛡️ [신선 비트겟] 시스템 허점 분석 및 보안/트레이딩 고도화 보고서 _1

## 1. 개요 및 분석 배경
본 보고서는 폐하의 어명에 따라 현재 구동 중인 **[신선 비트겟 (ShinSeon Bitget) 자동 트레이딩 시스템 V4.95]**의 **소스 코드, 서버 로그(`server.log`), 설정 파일(`server_config.json`), 네트워크 및 트레이딩 엔진 로직**을 총체적으로 감사(Audit)하여 발견된 시스템 허점, 보안 취약점, 트레이딩 로직의 구조적 한계를 분석하고 이를 완비하기 위한 최상위 고도화 대책을 제안합니다.

---

## 2. 🚨 시스템 5대 취약점 및 구조적 허점 정밀 분석

### 1) 🔓 [보안] API Key 및 텔레그램 토큰의 평문(Plaintext) 저장 위험
- **실태**: `server_config.json` 내에 비트겟 API Key, Secret Key, Passphrase, 텔레그램 Bot Token, Chat ID가 **암호화 없이 평문 텍스트**로 저장되어 있습니다.
- **위험성**: AWS 서버에 비인가 접속이 발생하거나 파일 접근 권한 오남용 발생 시, 거래소 API Key가 유출되어 자금 조작 또는 포지션 무단 강제 집행 위험에 노출될 수 있습니다.

### 2) ⏳ [트레이딩] 포지션 타임아웃 부재 및 "진입 락(Lock) 파라독스"
- **실태**: 포지션이 1개라도 잡히면(`is_position_active = True`), 목표 익절가(`+0.90%`)나 손절가(`-0.5%`)에 도달하기 전까지 **수십 시간 동안 횡보하더라도 포지션을 무한 유지**합니다.
- **위험성**: 시장 세션이 변경되거나 변동성이 사그라든 후 반대 방향의 강력한 역추세 신호가 나와도 포지션 락에 걸려 **추가 타점을 잡지 못하고 자금이 장기간 묶이는 자본 효율성 저하 현상**이 발생합니다.

### 3) ⚠️ [안전성] 거래소 하드웨어 스탑로스(Exchange TP/SL) 부재
- **실태**: 손절/익절이 AWS 서버의 소프트웨어 감시 루프(`manage_v35_exit_guardrail`)에서 초 단위로 감시하여 시장가 주문을 쏘는 구조입니다.
- **위험성**: 만약 AWS 서버 네트워크가 일시 불통되거나 비트겟 API 서버 장애, 혹은 서버 프로세스다운이 발생할 경우 **손절 신호가 나가지 않아 강제 청산(Liquidation)당할 무방비 노출 구간**이 존재합니다.

### 4) ⚡ [슬리피지] 시장가 통주문 체결에 따른 체결 오차 위험
- **실태**: 진입 및 비상 청산 시 `FORCE_MARKET_UNCAPPED`로 통주문을 전량 발주합니다.
- **위험성**: 비트코인 호가창 유동성이 순간 얇아진 상태에서 급격한 빔이 쏠 경우, 깊은 슬리피지(체결 오차)가 발생하여 손실 폭이 커질 수 있습니다.

### 5) 📡 [네트워크] WSS 재연결 시 상태 불일치(Stale State) 위험
- **실태**: 바이낸스/비트겟 웹소켓 단선 후 재연결 시, 잔고 및 포지션 동기화 간격(0.3초) 동안 미세한 메모리-거래소 간 상태 불일치가 일어날 가능성이 있습니다.

## 3. 🛡️ 보안 및 성능 고도화 정공법 대책 (Plan A)

| 구분 | 현상 및 문제점 | 최상위 고도화 대책 (정공법) |
|---|---|---|
| **API 보안** | 평문 JSON 파일 저장 | ① AWS Elastic IP (`13.192.187.244`) **비트겟 API IP 화이트리스트 고정**<br>② `cryptography` AES-256 대칭키 암호화 저장 |
| **포지션 제어** | 무한 홀딩 및 타점 락 | ① **시간 기반 타임아웃 청산(Time Exit)** (예: 45분간 횡보 시 본전/소폭 정리)<br>② **반대 신호 강제 스위칭(Signal Reversal)** 구현 |
| **청산 안전망** | 소프트웨어 감시 단일 의존 | 진입 성공과 동시에 **비트겟 거래소 온체인 서버에 Hard TP/SL Conditional Order 동시 기재** (2중 안전망) |
| **슬리피지** | 시장가 100% 통발주 | **슬리피지 가드레일 (Max 0.15%) 지정가 IOC 분할 주문** 모드 도입 |
| **네트워크** | WSS 단선 후 재연결 | WSS 재연결 직후 `sync_position_state_from_exchange()` 동기 직송 검증 |
