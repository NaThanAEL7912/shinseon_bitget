# [기획서 24] AWS 서버 텔레메트리 로그 폭주 도배 정화 및 클라이언트 중복 로그 필터링 (V4.29)

## 1. 개요 및 로그 이상 분석 결과
- **폐하의 지시 내용:**
  "로그 한번 확인 해볼레 뭔가 이상하다."
- **로그 정밀 추적 팩트 확인:**
  1. **AWS 서버 로그(`server.log`) 폭주 원인:**
     - `shinseon_server.py`의 0.1초 텔레메트리 루프에서 불려지는 `ui_callback()` 함수 내부에 `logger.info(f"[UI] {msg}")` 코드가 작성되어 있었습니다.
     - 이로 인해 1초에 10번(시간당 36,000번)씩 똑같은 `INFO:ShinseonBot:[UI] 100% 현금 대기 중 (저격 대기)` 로그가 파일에 쉼 없이 무한 도배되는 현상이 발생했습니다.
  2. **클라이언트 대시보드 로그창 도배 원인:**
     - 클라이언트(`shinseon_client.pyw`)에서도 `ui_update` 메시지를 수신할 때 `payload['msg']`가 기존 상태 메시지와 일치함에도 매초 불필요하게 `add_log()`를 호출하여 대시보드 로그 상자가 똑같은 문구로 채워지고 있었습니다.

## 2. 상세 수정 및 정화 계획

###가. AWS 서버 로그 폭주 도배 정화 (`shinseon_server.py`)
1. `ui_callback()` 내부의 `logger.info(f"[UI] {msg}")` 무조건 출력 구문을 삭제 또는 **상태가 변경되었을 때만 1회 기록하는 가드(Guard)**로 변경.
2. 0.1초 단위 실시간 브로드캐스트(웹소켓 직통 연동)는 그대로 100% 속도로 유지하되, 서버 파일 로깅만 깔끔하게 정돈.

###나. 클라이언트 대시보드 상태 로그 필터링 (`shinseon_client.pyw`)
1. `ui_update` 핸들러에서 단순 상태 텍스트(`100% 현금 대기 중` 등)는 오더플로우 레이더 및 상태 라벨에만 실시간 렌더링하고, **대시보드 알림 로그창에는 실질적인 거래/체결/설정변경 로그만 선택적으로 기록**하도록 필터링 적용.
2. 버전 번호를 `V4.29`로 상향 업데이트.

###다. 배포 및 검증
1. `deploy.py V4.29` 실행하여 Commit 및 GitHub main push.
2. `shinseon_server.py`를 AWS 서버(`13.192.187.244`)에 업로드 및 재가동.
3. AWS `server.log` 및 클라이언트 대시보드 로그창이 깨끗하고 안정적으로 기록되는지 검증.
