01 프로젝트 개요 및 목표

신선(ShinSeon) 프로젝트란?

신선 비트겟 시스템은 전 세계 최대 거래량을 자랑하는 Binance 선물 시장의 세력 오더플로우 데이터를 극초음속으로 스캐닝하여 Bitget 거래소에 0.0019초(1.9ms) 내외로 시장가 타점을 꽂아넣는 '초고속 오더플로우 융합 자동 트레이딩 봇'입니다.

[🔥 극초음속 스캐닝 엔진 스펙]
  • 청산(Liquidation) 수집: 실시간 (0초 딜레이)
    바이낸스 WebSocket을 통해 청산 이벤트 발생 즉시 서버로 다이렉트 푸시(Push)됩니다.
  • 미결제약정(OI) 스캐닝: 0.2초 단위 폴링
    1초에 5번씩 타격하며 세력 자금의 유입/유출을 초정밀 감시합니다.
  • 딥다이브 레코더(CSV): 1초 상시 기록 (12대 영문 표준 칼럼)
    사후 완벽한 복기 및 퀀트 통계 분석을 위해, 조건이나 임계치를 따지지 않고 24시간 내내 1초 간격으로 초고밀도 폭포수 로깅을 수행합니다.
핵심 철학 (The Core Philosophy) "세력의 진짜 신규 자금(+OI)이 터지는 순간에만 탑승하라."

개미들의 손절(-OI) 찌꺼기 휩쏘를 100% 기각하고, 스마트머니(세력)가 숏/롱 청산 물량을 먹어치우며 폭발적인 신규 자금(+OI)을 쏟아붓는 진짜 돌파 변곡점만 타격합니다.
최종 목표 (The Ultimate Goal) 인간의 감정과 뇌동매매를 100% 배제하고, 수학적 임계치와 1차/2차 듀얼 분할 익절 가드레일에 기반하여 '무손실에 가까운 안전성과 폭발적인 복리 수익'을 기계적으로 실현합니다.

03 핵심 판단 코어 엔진 (V6.39)

🚨 순수 +OI 세력 자금 절대 룰 (0단계 듀얼 임계치)

주문이 발생하기 위한 최소한의 자격 요건입니다. 이 두 가지가 동시에 충족되지 않으면 시스템은 절대 움직이지 않습니다.

rolling_1m_liq_usd >= target_liq
AND
oi_delta_1m > 0 AND oi_delta_1m >= target_oi

📊 1단계: 순수 +OI 2대 정통 돌파 저격 매트릭스 (V6.25)

Case 1분 EMA 추세 기울기 (price_slope_1m) 1분 OI 속도 (oi_delta_1m) 롱/숏 청산 주도 비율 2차 검증 오더플로우 팩트 (세력의 의도) 신선 포지션
Case C 지속 상승 ( > 0 ) 증가 ( > 0 ) short_liq ≥ long_liq (숏 청산 돌파) 세력이 숏 청산 먹으며 신규 매수 폭발. 상승 추세 돌파. LONG (매수) 🟢
Case D 지속 하락 ( < 0 ) 증가 ( > 0 ) long_liq ≥ short_liq (롱 청산 돌파) 세력이 롱 청산 먹으며 신규 숏 폭발. 하강 추세 돌파. SHORT (매도) 🔴
기각 -OI(음수) 잔파도, 임계치 미달, 청산 주도 세력 불일치 시 위험 휩쏘 및 개미 손절 잔파도 100% 원천 차단. NONE (휴식) ⚪️

🛡️ 2단계: 1차/2차 듀얼 계단식 분할 익절 & 초고속 쿨타임 (V6.39)

  • 1차 분할 익절 (+0.40% / +1.50%): 보유 수량의 50%를 시장가로 즉시 익절하여 확정 수익을 챙기고, 남은 50%의 손절선을 본전/버퍼 가드(+0.10% / +1.00%)로 상향하여 '1원도 잃지 않는 무위험 상태'로 전환합니다.
  • 2차 최종 익절 (+0.60% / +1.70%): 남은 50% 수량을 전량 시장가로 익절하여 2단계 대추세 완주를 달성합니다.
  • 진입 직후 60초 락다운: 진입 직후 60초간의 잔파도 페이크 청산을 완벽 차단합니다.
  • 초고속 쿨타임 (Fast Rotation): 익절 쿨타임 10초 / 손절 쿨타임 30초로 설정하여, 익절 후 10초 만에 다음 황금 파도에 초고속 재탑승합니다.

04 전술 기능 상세 명세서

1. 스마트 수량 가드 (400172 방어)

Why: 비트겟의 최소 주문 수량 제약(BTC의 경우 0.001 또는 0.0001)으로 인해 분할 익절 시 잔여 수량이 최소 수량 미만이 되면 API 에러(400172)가 발생하여 포지션이 갇히는 버그를 방지하기 위함.

How: 매도/익절 패킷을 생성하기 전, 현재 수량과 계산된 분할 수량을 비교하여 분할 수량이 0.0001 BTC 미만일 경우, 시스템이 자동으로 '전량 청산(100%)'으로 주문 파라미터를 강제 치환합니다.

2. 지능형 가드레일 (본전 가드 & 2단계 분할익절)

Why: 수익을 확보한 상태에서 갑작스러운 빔(Beam)을 맞아 손실로 전환되는 것을 완벽히 차단하고, 추세를 끝까지 발라먹기 위함.

How:
▹ 1차 익절: 목표 수익률 도달 시 50% 수량 시장가 익절.
▹ 본전/버퍼 가드: 1차 익절 직후 스탑로스를 본전가(+0.10%)로 자동 올려 무위험 상태 전환.
▹ 2차 최종 익절: 2차 목표가 도달 시 잔여 수량 전량 최종 익절.

3. 눌림목 불타기 (Pyramiding)

Why: 확실한 추세가 터졌을 때, 1차 익절 후 남은 물량에 수익금을 엎어서 비중을 다시 늘려 극대화된 수익을 창출하기 위함.

How: 1차 분할 익절이 나간 상태에서, 기존 진입 방향과 동일한 깃발의 강한 신호가 다시 발생하면, 초기 진입 수량의 30%를 시장가로 추가 진입(불타기)하고 평균단가를 재조정합니다.

4. 초고밀도 CSV 딥다이브 레코더

Why: 향후 AI 머신러닝 훈련 및 완벽한 사후 복기 백테스팅을 위한 12대 영문 표준 로우(Raw) 데이터를 수집하기 위함.

How: 어떠한 조건에도 구애받지 않고 무조건 1초 간격 상시 초고밀도 로깅 모드(Deep Dive)로 12대 표준 칼럼 데이터를 24시간 쏟아냅니다.

05 클라이언트 대시보드 (관제 모니터) 제어 패널

🔄 실전 계좌 잔고 동기화

Why: 거래소 앱을 켜지 않고도 봇의 현재 시드 머니 상태를 직관적으로 파악하기 위함.

How: 원클릭으로 비트겟 REST API를 호출하여 최신 총 자산 및 가용 USDT를 대시보드에 즉시 렌더링합니다.

📡 실시간 오더플로우 레이더

Why: 봇이 바이낸스 세력의 움직임을 제대로 스캐닝하고 있는지 1초 단위로 시각화하여 확인하기 위함.

How: 청산액과 OI 속도를 게이지바로 표시하며, 목표 임계치에 도달할 경우 황금빛 시각 알람을 제공합니다.

🕹️ 봇 상태 및 가드레일 제어

Why: 장세가 극도로 혼탁할 때 봇의 신규 진입을 수동으로 즉시 차단하거나, 가드레일 기능을 ON/OFF 하기 위함.

How: 대시보드의 직관적인 토글 스위치를 통해 봇 가동/정지, 본전가드, 분할익절 기능을 클릭 한 번으로 제어합니다.

🚨 비상 마스터 탈출

Why: 붓다빔, 머스크빔 등 초거대 악재 발생 시, 고민할 시간 없이 즉시 봇을 멈추고 시드를 보호하기 위한 최후의 보루.

How: 버튼 클릭 즉시 진행 중인 모든 프로세스를 중단하고 0.5초 만에 현재 포지션을 전량 시장가로 던진 뒤 봇 가동을 정지합니다.

🔪 50% 시장가 분할 청산

Why: 수동으로 빠르게 반익절(50%)을 날려 리스크를 축소하기 위함.

How: 버튼 클릭 시 400172 스마트 수량 가드를 거쳐 안전하게 절반의 포지션을 즉시 시장가 청산합니다.

🎯 스마트 스탑 & 목표가 알림

Why: 폐하께서 자리를 비우시거나 주무실 때, 미리 지정해 둔 핵심 지지/저항선이 뚫렸을 경우 시드를 방어하기 위한 절대 방어선.

How: 지정 가격 관통 시 0.5초 이내에 보유 중인 전량 포지션을 시장가로 강제 손절/익절하고 텔레그램으로 즉각 보고합니다.

08 🛠️ 유지보수 가이드 (Troubleshooting)

오류 발생 시 개발자가 가장 먼저 확인해야 할 원포인트 점검 가이드입니다.

  • 증상: 비트겟 주문이 안 나가거나 에러가 뜸 (예: 400172)
    해결: shinseon_server.py의 _execute_bitget_internal_packet_impl() 함수 내부를 확인하십시오. 잔여 수량(size) 처리 로직과 FORCE_MARKET_UNCAPPED 파라미터가 정확히 들어갔는지 점검해야 합니다.
  • 증상: 오더플로우 깃발(LONG/SHORT) 방향이 엉뚱하게 뜰 때
    해결: shinseon_server.py의 _process_1m_data_and_trade_impl() 함수 내 Case C, D 분기문을 확인하십시오. price_slope_1m(EMA 기울기), oi_delta_1m > 0, short_liq vs long_liq 판단이 백서와 일치하는지 대조해야 합니다.
  • 증상: 클라이언트와 AWS 서버 간 로그 동기화가 끊어짐
    해결: shinseon_server.py의 웹소켓 서버 및 EVT_SYNC_TELEMETRY 푸시 로직을 점검하십시오.
  • 증상: CSV 장부 파일이 저장되지 않음
    해결: shinseon_server.py 내부의 _write_csv_impl() 호출부 예외 처리 로그를 확인하십시오.
