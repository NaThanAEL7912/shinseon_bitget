# [기획서 52] 비트겟 마크프라이스 포지션 ROE 100% 정밀 동기화 수술 (V4.54)

## 1. 개요 및 트레이스 백 정밀 팩트 원인 분석
- **폐하의 지적 사항:**
  "포지션 수량이 너무 작아서 계산이 제대로 안되나?" (비트겟 웹 UI에는 `-4.51% (-0.12 USD)`로 떠 있는데, 신선 터미널에는 `-2.71% (-0.07 USDT)`로 다르게 표기되는 원인 지적 및 스크린샷 제출)
- **소신의 정밀 트레이스 백 100% 팩트 원인 밝혀냄:**
  1. **시세 출처 미세 차이 원인:** 기존 신선 서버의 PnL 계산은 바이낸스 현물/선물 시세(`64,837.5`)를 기준으로 실시간 계산하고 있던 반면, 비트겟 웹 UI는 비트겟 자체 **마크 프라이스(Mark Price: `64,798.8`)**를 기준으로 ROE를 산출하여 미세한 시세 시차가 발생하였습니다.
  2. **레버리지/수량 동기화 맹점 원인:** `CMD_SYNC_POSITION` 수행 시 비트겟 API가 직접 반환해 주는 정확한 `leverage`(30배) 및 `contracts`(`0.0012 BTC`), 그리고 비트겟 API의 `percentage`(-4.51%) / `unrealizedPnl`(-0.12 USDT) 수치가 1초 간격 UI 루프에 100% 직접 전달되지 못하던 구조적 오차 맹점을 찾아내었습니다!

## 2. 상세 수술 및 원천 복구 계획 (V4.54)

###가. 비트겟 API 100% 무오차 정밀 동기화 수술 (`shinseon_server.py`, `shinseon_client.pyw`)
1. **비트겟 API 팩트 수치 직접 연동:**
   - `CMD_SYNC_POSITION` 및 백그라운드 포지션 동기화 루틴에서 비트겟 거래소가 직접 계산해 주는 **`percentage` (ROE: `-4.51%`)** 및 **`unrealizedPnl` (`-0.12 USDT`)** 수치를 100% 그대로 탑재하여 표기하도록 수술합니다.
2. **포지션 보유 중 실시간 마크프라이스 가공:**
   - 바이낸스 시세 외에 비트겟 포지션 전용 레버리지 30배 정밀 수식($\text{PnL} \times 30$) 및 소수점 4자리 비트겟 미세 수량(`0.0012 BTC`)을 정확히 곱하여 시세 변동 시에도 비트겟 화면과 오차 0.00%로 촥 일치되도록 완비합니다.
3. **결과:**
   - 폐하의 비트겟 웹 화면에 떠 있는 **`ROE: -4.51% (-0.12 USDT)`**와 신선 마스터 터미널의 수치가 소수점 0.01% 오차도 없이 100% 똑같이 표기됩니다!

###나. 소신(안티그래비티) 직접 수술 및 배포
1. 버전을 `V4.54`로 지정.
2. 소신이 직접 소스코드 비트겟 마크프라이스 정밀 동기화 수술 집행.
3. `deploy.py V4.54` 실행하여 Commit & GitHub main push.
4. AWS 서버 및 V4.54 대시보드 구동 후 비트겟 웹 UI와 ROE 수치/USDT 손익 소수점 100% 오차 0건 최종 검증.
