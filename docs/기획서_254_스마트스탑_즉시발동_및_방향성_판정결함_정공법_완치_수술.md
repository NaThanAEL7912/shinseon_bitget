# 기획서 254: 스마트 스탑 가드 즉시 발동 및 양수/음수 명확 판정 정공법 완치 수술

## 1. 개요 및 배경
폐하께서 스마트 스탑 가드를 `1.0% ROE (비중 100%)`로 설정하셨고, 실시간 화면에 `ROE: +1.03%`로 목표치(1.00%)를 초과 달성했음에도 불구하고 **스마트 스탑 청산 주문이 나가지 않고 계속 감시 중으로 머물러 있던 현상**에 대하여 긴급 정밀 진단을 수행하였습니다.

---

## 2. 🚨 결함 원인 정밀 팩트 규명 (진범 2가지)

1. **[진범 1] `pnl_at_set` 기반 모드 오판정 결함 (상방/하방 임의 추정 버그)**:
   - 기존 로직은 스마트 스탑 버튼을 누를 당시의 실시간 ROE(`pnl_at_set`)와 사용자가 입력한 오프셋(`offset_val`)을 비교하여 상방/하방을 결정했습니다.
   - 만약 버튼을 누를 당시 이미 ROE가 `+1.03%`인 상태에서 오프셋 `1.0`을 눌렀다면, 시스템이 `1.0 < 1.03`으로 인식하여 이를 **"1.0% 이하로 떨어지면 던지는 하방 모드"**로 오판정하였습니다!
   - 그 결과, 현재 ROE가 `+1.03%`로 1.0%를 넘었음에도 불구하고 "1.0% 이하로 떨어지지 않았다"며 청산을 안 하고 버티는 치명적 오류가 발생했습니다.

2. **[진범 2] `CMD_SET_SMART_STOP` 패킷 처리부 내 `entry_dir` 미선언 결함**:
   - `shinseon_server.py`의 `CMD_SET_SMART_STOP` 처리부에서 감시 테스크(`manage_v35_exit_guardrail(entry_dir)`)를 구동할 때 `entry_dir` 변수가 선언되지 않아 `NameError`로 루프 가동이 스킵될 위험이 있었습니다.

---

## 3. 🛠️ 정공법 완치 수술 계획

1. **양수/음수 절대 기준 기반 즉시 발동 수술 (추정 로직 폐기)**:
   - **양수 오프셋 (`offset > 0`, 예: +1.0%)**:
     - 무조건 **[목표 익절 모드]**로 직결!
     - `실시간 ROE >= 설정 오프셋` (현재 ROE가 1.0% 이상이면 0.01초 만에 즉시 100% 시장가 청산 발주!)
   - **음수 오프셋 (`offset < 0`, 예: -0.8%)**:
     - 무조건 **[스탑로스 손절 모드]**로 직결!
     - `실시간 ROE <= 설정 오프셋` 이면 즉시 시장가 청산 발주!
   - **0% 오프셋 (`offset == 0.0`)**:
     - **[본전 가드 모드]** ➔ `실시간 ROE <= 0.00%` 즉시 청산!

2. **스마트 스탑 설정 즉시 1차 검사(Instant Trigger) 추가**:
   - 사용자가 버튼을 누른 즉시, 만약 이미 실시간 ROE가 조건을 충족하고 있다면 루프 대기 없이 **그 자리에서 즉각 비트겟 시장가 청산을 0.1초 만에 집행**합니다.

3. **`entry_dir` 안전 선언 및 AWS 서버 실시간 배포(`deploy.py`)**:
   - `shinseon_server.py`의 패킷 처리부 완치 및 배포.
