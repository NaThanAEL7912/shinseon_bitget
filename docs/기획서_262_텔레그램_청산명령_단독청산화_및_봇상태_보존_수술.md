# 🏛️ [기획서 262] 텔레그램 '청산' 명령의 봇 상태 보존 및 독립 청산 로직 분리 수술

> **상태:** 📋 **[기획안 대기 / 원복 완료]** (폐하의 검토 및 별도 지시 대기 중)

---

## 1. 문제 원인 정밀 진단 (Problem Analysis)

### 1.1 현상
- 텔레그램에서 폐하께서 **"청산"** 또는 **"/close"** 명령을 전송했을 때, 비트겟 포지션 청산과 함께 **봇의 구동 상태가 강제로 ot_state = "STOPPED", is_snipe_active = False 로 변경**되어 자동 감시가 멈추는 결함 발생.

### 1.2 소스코드 결함 지점 (shinseon_server.py 라인 699~706)
- "청산"과 "비상탈출"이 한 분기문으로 묶여 있어, 단순히 현재 포지션만 정리하고 다음 타점을 계속 노리고자 했던 봇의 실행 상태(RUNNING)가 강제로 꺼지는 문제가 발생함.

---

## 2. 해결 방안 및 정공법 설계 (Solution Design)

### 2.1 텔레그램 원격 명령 체계의 명확한 3단 독립 분리 (기획안)

| 명령어 | 대상 동작 | 봇 구동 상태(ot_state) | 설명 |
|:---|:---|:---|:---|
| **청산, /청산, /close, 전량청산** | **비트겟 포지션 100% 시장가 청산만 집행** | **기존 상태 유지 (RUNNING 유지)** | 포지션만 정리 |
| **50%청산, /half, 절반청산** | **비트겟 포지션 50% 분할 청산만 집행** | **기존 상태 유지 (RUNNING 유지)** | 50% 분할 익절 |
| **비상탈출, /emergency, /비상탈출** | **포지션 100% 청산 + 봇 완전 정지** | **STOPPED (완전 정지)** | 위급 시 셧다운 |
| **정지, /정지, /stop** | **포지션 유지 + 봇 감시만 정지** | **STOPPED (감시 정지)** | 봇만 대기 모드 |
| **시작, /시작, /start** | **봇 자동 감시 가동** | **RUNNING (감시 가동)** | 자동 저격 활성화 |
