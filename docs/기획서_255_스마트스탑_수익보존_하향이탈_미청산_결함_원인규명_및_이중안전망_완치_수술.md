# 기획서 255: 스마트 스탑 수익보존(ROE 2.0% ➔ 1.0% 하향 이탈) 미청산 결함 원인 규명 및 텔레메트리 이중 안전망 정공법 완치 수술

## 1. 개요 및 배경
폐하께서 실시간 ROE가 `+2.0%`일 때 수익 보존을 위해 스마트 스탑 오프셋을 `1.0%`로 설정하셨으나, 이후 ROE가 `+0.9%`로 1.0% 이하로 하향 이탈했음에도 불구하고 **스마트 스탑 청산 주문이 나가지 않았던 치명적 결함**에 대해 원인을 100% 명확히 규명하고 영구 완치 수술을 진행합니다.

---

## 2. 🚨 결함 원인 100% 팩트 규명 (진범 3가지)

1. **[진범 1] `entry_dir` 미선언 NameError로 인한 스마트 스탑 감시 루프 사망**:
   - `CMD_SET_SMART_STOP` 수신 시 `manage_v35_exit_guardrail(entry_dir)`를 호출하는 코드에서 `entry_dir` 변수가 선언되지 않아 `NameError` 예외가 발생하여 감시 프로세스가 팝업되지 않고 증발했습니다.
2. **[진범 2] 화면 텍스트(텔레메트리)와 실제 감시 엔진의 완전 분리 결함**:
   - 텔레메트리 루프는 변수만 보고 화면에 `(🔮 스마트 스탑 가드: +1.00% ROE 익절 감시 중)` 라벨을 계속 찍어주었으나, 정작 뒤에서 가격을 체크하고 발주하는 감시 엔진은 멈춰 있었습니다.
3. **[진범 3] 청산 실행 엔진의 단일 의존성 취약점**:
   - 1초마다 상시 가동되는 `run_telemetry_loop` 내에 스마트 스탑 청산 집행기가 탑재되어 있지 않아, 감시 루프가 멈추면 영원히 청산이 나가지 않는 구조적 취약점이 있었습니다.

---

## 3. 🛠️ 정공법 완치 수술 상세 명세

1. **`CMD_SET_SMART_STOP` 패킷 처리부 완치**:
   - `entry_dir = getattr(v35, "entry_direction", None) or getattr(v35, "position_side", "LONG") or "LONG"`로 안전하게 포지션 방향을 가져와 감시 루프를 100% 확실하게 팝업 가동.
   - `pnl_at_set` (설정 시점 ROE) 정확한 동기화 (예: 2.0%일 때 설정 시 `pnl_at_set = 2.00`).
   - `offset_val (1.0) < pnl_at_set (2.0)` ➔ **하방 수익보존 모드(`live_roe <= 1.0`)** 100% 정상 작동 보장.

2. **텔레메트리 루프(`run_telemetry_loop`) 내 스마트 스탑 청산 실행기 이중 탑재**:
   - 1초마다 도는 메인 텔레메트리 루프에서도 `custom_stop_active`를 실시간 감시하여,
   - `live_roe <= offset_val` (하방) 또는 `live_roe >= offset_val` (상방) 충족 시 **즉시 비트겟 100% 시장가 청산(`FORCE_MARKET_UNCAPPED`)을 0.1초 만에 발주**하도록 이중 안전망을 구축합니다.

3. **AWS 서버 즉시 배포 및 실시간 가동**:
   - `deploy.py`를 통해 AWS 서버에 즉시 무중단 배포 및 검증.
