# ShinSeon Bitget 기획서_129 (서버 API키 연동 보증 및 클라이언트 직송 2중 체결 복원 엔진 완공)

## 📌 개요
AWS 서버 환경에서 거래소 CCXT 인스턴스(`bitget_exchange`) 미초기화로 인해 체결 복원 조회가 차단되던 팩트 원인을 규명하고, **클라이언트 CCXT 직접 스캔 & 서버 직송 2중 체결 복원 엔진** 및 **서버 API키 자동 동기화**를 완공하여 팝업 표에 100% 매매 실적이 선명하게 출력되도록 수술합니다.

---

## 🔍 [원인 분석 및 2중 복원 수술안]

1. **원인 팩트:**
   - 서버의 `bot_core.bitget_exchange` 객체는 `server_config.json`에 비트겟 API 키가 입력되어야 가동되는데, AWS 서버 단독 환경에서 API 키 파라미터가 연결되지 않아 `bitget_exchange`가 `None` 상태였음.
   - 이로 인해 `sync_past_bitget_trades_7d`가 거래소 조회를 시작하지 못하고 바로 리턴되어 실적이 표에 나타나지 않았음.

2. **2중 철통 복원 수술안 (정공법 1안):**
   - **1방어 (클라이언트 직송 융합):** 클라이언트(`shinseon_client.pyw`)는 비트겟 API 키를 보유하고 있으므로, `[🔄 실시간 새로고침]` 클릭 시 클라이언트 CCXT에서 최근 7일치(100건) 체결 내역을 스캔하여 서버로 복원 패킷(`CMD_REQ_STATS_SYNC_RECOVERY`)을 송신 ➡️ 서버가 `logs/trade_stats_YYYY-MM-DD.json` 일별 통계 로그 파일에 100% 자동 정격 기록 및 렌더링.
   - **2방어 (서버 API키 자동 세팅):** 클라이언트 접속 시 전달받은 API 키 정보를 `bot_core.bitget_exchange`에 즉시 할당하여 서버 단독 조회도 100% 작동하도록 보증 (V5.28).
