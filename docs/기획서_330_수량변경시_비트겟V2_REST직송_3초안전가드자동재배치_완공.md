## 1. 🎯 [기획 배경 및 팩트 확인]

### 1) 폐하의 질문
- *"지금 개발 내역에는 물량이 변경 되었을 경우에는 안전가드 재 설정이 없냐?"*

### 2) 팩트 분석 및 원인 규명
1. **설계된 로직:**
   - `shinseon_server.py`의 `sync_bitget_real_position_status()` (라인 1757)에 이전 수량(`prev_contracts`)과 현재 수량(`v_contracts`)의 차이가 발생하면 `is_pos_changed = True`로 판정하여 `place_bitget_tpsl_plan_orders()`를 자동 호출하도록 설계되어 있었습니다.
2. **미작동 팩트 원인 (CCXT 비동기 세션 지연):**
   - 포지션 조회를 `ccxt.bitget.fetch_positions()`로 수행하는데, CCXT 라이브러리 내부에서 전체 마켓 메타데이터 로딩(`load_markets`) 시도 시 간헐적 딜레이 또는 `pass` 예외 블록으로 빠지면서 수량 변경 이벤트를 실시간으로 감지하지 못하는 현상이 발생하였습니다.
3. **정공법 해결책:**
   - 딜레이나 예외가 없는 **비트겟 공식 V2 REST API (`/api/v2/mix/position/all-position`) 직송 통신**으로 포지션 조회를 전환하여, **수량이나 평단가가 0.0001 BTC라도 변경되면 3초 이내에 기존 구형 플랜 주문을 즉시 100% 취소하고 신규 수량 기준으로 1차 TP(50%) / 2차 TP(50%) / SL(100%)을 자동 재발주**하도록 무결성을 확보합니다.

## 2. 🔍 [정공법 완치 및 배포 설계]

1. **`sync_bitget_real_position_status`를 비트겟 V2 REST API 직송으로 교체:**
   - CCXT 대신 aiohttp를 통한 초경량 비트겟 V2 REST API (`/api/v2/mix/position/all-position`) 다이렉트 호출.
   - `contracts` 및 `entryPrice`의 실시간 변동을 3초마다 100% 무결하게 감지.
2. **수량 변경 시 자동 재배치 파이프라인:**
   - 수량 변경 감지 ➡️ 기존 잔여 플랜 주문 전량 캔슬(`cancel-plan-order`) ➡️ 신규 수량(`v_contracts`) 기준 3대 안전가드 즉시 재발주(`place-tpsl-order`).
3. **V7.38 삼위일체 버전 동기화 및 AWS 도쿄 서버 배포:**
   - `deploy.py V7.38`를 통해 AWS 실전 서버로 SFTP 배포 및 데몬 핫-리로드.
   - 현재 폐하의 실계좌(`0.0533 BTC` @ `$78,697.25`)에 대해 3대 안전가드 자동 재배치 팩트 검증.
