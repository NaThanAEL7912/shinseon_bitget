## 1. 배경 및 문제점 분석 (Root Cause Analysis)

### 1.1 현상
- 클라이언트의 **[가드레일 설정]** 탭에는 세션별로 **[1차 익절 PnL (%)]**과 **[2차 익절 PnL (%)]**, 그리고 하단에 **[1차 분할 익절 비율(50%)]** / **[2차 분할 익절 비율(50%)]**이 명확히 정의되어 있으나,
- 실제 비트겟 거래소에는 **1차 익절 플랜 주문 1개만 발주**되어, 2차 최종 익절 목표가가 거래소 차트에 등록되지 않고 누락되고 있었음.

### 1.2 원인 분석 (shinseon_server.py L1946~1968)
- 	p_body가 1차 익절(	rigger) 목표가 1개만 생성하여 전송하고 있었으며, 	rigger_2(2차 익절)에 대한 2차 분할 주문 전송 로직이 누락되어 있었음.

## 2. 정공법 해결 설계 (Technical Solution)

### 2.1 UI 가드레일 설정값 1:1 완전 연동 듀얼 TP 발주 체계 구축 완료

`
┌────────────────────────────────────────────────────────────────────────┐
│ 💰 【1차 분할 익절 주문 (1st Partial TP)】:                            │
│    • 발동 목표가: 진입가 ± (세션별 1차 익절 PnL %, 예: +0.40% ~ +1.00%) │
│    • 청산 수량: 전체 진입 수량 × (1차 분할 익절 비율 %, 예: 50.0%)      │
│    • API 파라미터: planType = "profit_plan"                            │
├────────────────────────────────────────────────────────────────────────┤
│ 🚀 【2차 분할 익절 주문 (2nd Partial TP)】:                            │
│    • 발동 목표가: 진입가 ± (세션별 2차 익절 PnL %, 예: +0.60% ~ +1.20%) │
│    • 청산 수량: 전체 진입 수량 × (2차 분할 익절 비율 %, 예: 50.0%)      │
│    • API 파라미터: planType = "profit_plan"                            │
├────────────────────────────────────────────────────────────────────────┤
│ 🛑 【손절 주문 (Stop Loss)】:                                           │
│    • 발동 손절가: 진입가 ∓ (세션별 손절 PnL %, 예: -0.60% ~ -1.00%)     │
│    • API 파라미터: planType = "pos_loss"                               │
└────────────────────────────────────────────────────────────────────────┘
`

### 2.2 비트겟 API 발주 루프 개편 완료 (shinseon_server.py L1900~1975)
- 포지션 진입 시 거래소로 **[1차 TP(50%)] + [2차 TP(50%)] + [SL(100%)]** 총 3개의 안전 플랜 주문이 동시 자동 발주되도록 수술 완료.
