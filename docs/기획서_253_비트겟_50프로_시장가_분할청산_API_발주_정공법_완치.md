## 🎯 1. 개요 및 배경
- **현상 및 문제점:**  
  폐하께서 대시보드 우측 하단의 **`[ 🌓 50% 시장가 분할 청산 ]`** 버튼을 클릭하셨으나, 서버 로그상 비트겟 API로부터 `❌ [50% 청산 실패] No position to close (코드: 22002)` 에러가 반환되며 분할 청산이 체결되지 않는 현상이 발생하였습니다.
- **원인 분석:**  
  1. 서버의 50% 분할 청산 처리 블록(`_execute_bitget_internal_packet_impl` 라인 2206~2235)에서 raw aiohttp REST 호출 시 비트겟 v2의 `tradeSide: close`, `holdSide: long` 파라미터가 계정 포지션 모드(Hedge vs One-way) 및 기존 TP/SL 트리거 위임 상태와 충돌하여 22002 에러를 발생시켰습니다.
  2. 반면 전량 청산 블록(라인 2263~2267)에서 사용하는 **CCXT 정통 `exchange.create_order(symbol, 'market', close_side, amount, params={'tradeSide': 'close', ...})`** 및 `reduceOnly` 폴백 엔진은 검증된 표준 프로토콜로 체결됩니다.
- **목적:**  
  50% 시장가 분할 청산 발주부를 **CCXT 정통 `create_order` 엔진 및 계정 모드별 자동 폴백(Hedge Mode / One-way reduceOnly)** 으로 완벽히 일원화하여, 버튼 클릭 시 0.001초 만에 50% 분할 청산이 100% 무결하게 체결되도록 수술합니다.

## 🛠️ 2. 상세 작업 명세

### ① 50% 분할 청산 발주 파이프라인 수술 (`shinseon_server.py` 라인 2186~2256)
1. **정통 CCXT `create_order` 기반 50% 분할 청산 체결:**
   ```python
   # 50% 분할 수량 계산 (소수점 4자리 안전 라운딩)
   amount = round(total_contracts * ratio_factor, 4)
   if amount < 0.0001:
       amount = 0.0001
   
   close_side = "sell" if pos_side in ["long", "open_long"] else "buy"
   
   # 비트겟 CCXT 2중 방어 파라미터 구성
   if active_pos.get('info', {}).get('posMode') == 'hedge_mode' or active_pos.get('hedged', True):
       params = {'tradeSide': 'close', 'holdSide': pos_side.lower(), 'marginMode': 'isolated', 'marginCoin': 'USDT'}
   else:
       params = {'reduceOnly': True, 'marginMode': 'isolated', 'marginCoin': 'USDT'}
       
   order = await exchange.create_order(symbol, 'market', close_side, amount, params=params)
   ```
