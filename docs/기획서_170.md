# ShinSeon Bitget 기획서_170 (스마트 스탑 가드 기능 명세서 및 클라이언트 패킷 수송 완치안)

## 📌 1. 개요 및 스마트 스탑(Smart Stop) 기능 명세

### 1.1. 스마트 스탑이란?
스마트 스탑(Smart Stop)은 비트겟 선물 포지션 보유 중, 대시보드 UI 제어판에서 지정한 **[오프셋(%)]** 및 **[비율(%)]** 조건에 따라 **실시간 PnL/ROE를 24시간 감시하다가 조건 충족 시 비트겟 거래소로 시장가 청산을 즉각 자동 발주하는 세이프티 가드레일 기능**입니다.

### 1.2. 상세 동작 메커니즘
1. **오프셋(%) 감시 모드 자동 판정 (듀얼 방향성 엔진):**
   - **하방 손절/수익 보존 모드:** 설정한 오프셋(%) 값이 설정 시점의 ROE보다 **낮은 경우**
     - 예: 현재 ROE +1.5%일 때 오프셋 `0.8%` 입력 ➡️ 실시간 ROE가 `+0.8%` 이하로 하락하는 순간 **수익 보존 청산** 발동!
   - **상방 반등/목표 익절 모드:** 설정한 오프셋(%) 값이 설정 시점의 ROE보다 **높은 경우**
     - 예: 현재 ROE +0.5%일 때 오프셋 `3.0%` 입력 ➡️ 실시간 ROE가 `+3.0%` 이상으로 상승하는 순간 **목표 익절 청산** 발동!
2. **청산 비율(%) 지정:**
   - **`100%` 지정 시:** 포지션 전량 즉시 시장가 청산 (`FORCE_MARKET_UNCAPPED`).
   - **`1~99%` 지정 시:** 지정한 비율만큼 분할 시장가 청산 (`PARTIAL_CLOSE`).

## 🔍 2. 현재 기능 불능(작동 불가)의 팩트 원인 분석

1. **클라이언트(`shinseon_client.pyw`) 패킷 수송 단절 버그:**
   - 클라이언트 소스코드 내 `trigger_stoploss_setting()` 메서드가 `self.bot_core.v35_engine` 로컬 객체를 검사하는 구형 코드로 중복 덮어씌워져 있었습니다.
   - AWS 원격 연결 모드에서는 `self.bot_core`가 `None`이므로, 사용자가 `[스마트 스탑 설정]` 버튼을 누르는 순간 1초 만에 조기 종료(`return`)되어 **AWS 서버로 `CMD_SET_SMART_STOP` 수송 패킷이 쏘아지지 않고 100% 증발**하던 팩트가 확인되었습니다.
2. **서버(`shinseon_server.py`) 감시 루프 중복 코드:**
   - `manage_v35_exit_guardrail` 내부에 ROE 기준 블록과 Price PnL 기준 블록 2개가 중복 작성되어 있어 감시 판단이 혼선을 일으킬 가능성이 존재했습니다.
