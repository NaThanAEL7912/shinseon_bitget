# 기획서 200: 실전 비트겟 숏 신호 발생 시 주문 미체결 팩트 원인 규명 및 코드 수술 기획

## 1. 개요 및 배경
폐하께서 제공해 주신 실전 비트겟 거래소 계정 스크린샷 (가용 잔액 `13.5164 USDT`, 포지션 `Positions (0)`, 19:08:32 신호 발생에도 거래소 주문 미체결)을 바탕으로, **실전 비트겟 API 주문 발주가 거부되었거나 미동작한 3대 팩트 원인**을 점검하고, 숏 신호 발생 즉시 실전 주체 포지션이 비트겟에 100% 즉시 체결되도록 정공법 코드를 수술하는 기획서를 수립합니다.

---

## 2. 🔍 실전 주문 미체결 3대 팩트 원인 추정 및 정밀 검증 항목

1. **[원인 1] 비트겟 최소 주문 수량 (Min Quantity: 0.001 BTC) 및 소수점 정밀도 단위 미달**:
   - 가용 잔액 `13.5164 USDT` x 레버리지 30배 기준, 비중 계산 수량이 비트겟 API 최소 수량 단위(stepSize)와 일치하지 않아 비트겟 서버에서 `Order Rejected` 처리되었는지 검수.
2. **[원인 2] `shinseon_client.pyw` 내 실전 매매 집행 트리거 조건 누락**:
   - UI 레이더 상에서는 `SHORT` 신호가 표시되었으나, 실전 비트겟 REST API 주문 발주 루틴(`send_order` / `place_order`)으로 넘겨주는 연동 고리가 누락되거나 조건문에 걸렸는지 검수.
3. **[원인 3] API Key / Secret 연동 권한 및 예외 처리(Exception Swallowing)**:
   - 주문 생성 과정에서 선물 트레이딩 권한 미부여 또는 에러 예외가 발생했으나 에러 로그 표출 없이 무소식 처리되었는지 검수.

## 3. 🛠️ 정공법 코드 수술 및 개선 방안
- [ ] **[1단계]** `shinseon_client.pyw` 주문 발주 함수(`execute_order` / `send_order`)의 실전 API 호출 조건부 전수 점검
- [ ] **[2단계]** 비트겟 BTCUSDT 최소 주문 수량(`min_qty` = 0.001 BTC) 및 소수점 3자리(`round(qty, 3)`) 정밀 동기화 수술
- [ ] **[3단계]** 주문 실패 시 에러 사유(API Error, Balance Error, Min Qty Error)를 봇 로그 창 및 팩트 리포트에 100% 명확히 표출하도록 수술
- [ ] **[4단계]** 폐하께 최종 수술 보고 및 기획서 완료 갱신 / 프로젝트 버전 관리 업데이트
